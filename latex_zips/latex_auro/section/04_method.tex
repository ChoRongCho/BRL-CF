\section{Method}~\label{method:method}
Our method uses state uncertainty to determine query timing and query selection. A planner can select an action even if the state facts required for successful execution remain uncertain. Therefore, the robot needs a criterion for deciding whether additional state information is necessary before execution continues. After each action and observation, we construct a weighted belief over reachable symbolic states and measure belief confidence using normalized entropy. If confidence falls below a threshold, the robot requests state verification. Expected entropy reduction determines which fact to verify to reduce uncertainty among the remaining state hypotheses.

\subsection{Planning and Querying}~\label{method:overview}\label{method:planning}
% Fig.~\ref{fig:pm} summarizes the online planning loop. 
We maintain a committed knowledge state $s_t^{K}$ as the reference for symbolic planning and execution. Symbolic action preconditions and effects require a consistent assignment of task facts, as described in Sec.~\ref{preliminaries:STRIPS}. The Knowledge Base (KB) stores this assignment, and POMCP selects an action $a_t\in\mathcal{A}$ applicable to $s_t^{K}$, denoted by $a_t\llbracket s_t^{K}\rrbracket$. After the robot executes $a_t$ and receives observation $o_{t+1}$, we construct a weighted belief $\mathcal{B}_{t+1}$ over the symbolic successors reachable from $(s_t^{K},a_t)$. Each symbolic state is a subset of the atom set $\mathcal{F}$, so the complete state space contains up to $2^{|\mathcal{F}|}$ states. The local successor set makes belief construction practical during online execution and represents uncertainty in the outcome of the executed action.

Belief confidence determines whether the robot requests external confirmation. If confidence in $\mathcal{B}_{t+1}$ falls below the threshold $\tau$, the robot begins a query loop. At each iteration, the robot asks about a symbolic fact $c^*$ selected by expected entropy reduction and removes states inconsistent with the response. The remaining weights are renormalized before confidence is evaluated again. The loop ends if confidence reaches $\tau$ or no fact distinguishes the remaining states.

After the query loop, the most probable remaining state is committed as
\[
s_{t+1}^{K}=\arg\max_{s^k\in\mathcal{B}_{t+1}} w_k.
\]
The committed state $s_{t+1}^{K}$ provides the symbolic reference for the next planning step. The weighted belief supports confidence estimation and query selection before this commitment.

\label{method:PM}
POMCP~\cite{silver2010monte} evaluates robot actions through sampled state transitions. The search retains the standard simulation and value updates. Both tree expansion and rollout consider actions whose symbolic preconditions hold in the sampled state. For state $s$, the applicable action set is
\[
\mathcal{A}(s)=\{a\in\mathcal{A}\mid \mathrm{pre}(a)\subseteq s\}
\]
The generative model samples $(s',o,r)$ from the same domain transition and observation models used to construct the explicit frontier. This avoids evaluating symbolically infeasible actions while preserving stochastic search over reachable outcomes.

After perception and external feedback update the state estimate, the planner prunes the search tree using the executed action and the committed successor state. The next search therefore uses the state estimate obtained after verification. Appendix~\ref{appx:algorithms} provides the search, simulation, and rollout procedures.

\label{method:belief_rep}
The state representation combines symbolic facts with numeric fluents. Facts encode task conditions that affect action applicability, such as $\texttt{ripe}(\text{tomato}_1)$ or the waste category of an object. Numeric fluents encode quantities used by robot skills, such as object poses and distances. The feedback policy evaluates uncertainty in symbolic facts. Sensor observations update numeric values without expanding the symbolic hypothesis set.

The method constructs a local \emph{frontier} of successor states after each executed action. Given committed state $s_t^{K}$ and action $a_t$, the transition model returns the symbolic successors with nonzero probability.
\begin{equation}
\mathcal{F}_{t+1}
=
\mathrm{Frontier}(s_t^{K},a_t)
=
\{s_{t+1}^{1},\ldots,s_{t+1}^{j}\}.
\label{eq:frontier}
\end{equation}
Deterministic add and delete effects are applied directly, while uncertain outcomes instantiate mutually exclusive successor hypotheses defined by the domain model. Duplicate successors are merged. If the number of outcomes exceeds the particle budget, successors are sampled without replacement according to their transition probabilities. This construction restricts feedback decisions to states reachable from the current planning context.

The transition probability and observation likelihood jointly determine the weight of each frontier state after observation $o_{t+1}$.
\begin{equation}
\begin{aligned}
\bar{w}_{k}
&=T(s_{t+1}^{k}\mid s_t^{K},a_t)\,
O(o_{t+1}\mid s_{t+1}^{k},a_t),\\
w_k&=\frac{\bar{w}_k}{\sum_{\ell=1}^{j}\bar{w}_{\ell}}.
\end{aligned}
\label{eq:belief_update}
\end{equation}
If every unnormalized weight is zero, the implementation falls back to a uniform distribution over the represented frontier. The resulting belief is
\begin{equation}
\mathcal{B}_{t+1}
=
\{(s_{t+1}^{k},w_k)\}_{k=1}^{j},
\qquad
\sum_{k=1}^{j}w_k=1.
\label{eq:symbolic_belief}
\end{equation}
This explicit weighted frontier is used for confidence estimation and query selection. POMCP maintains sampled states in the search tree to estimate action values. Both components use the same symbolic transition and observation models.

\label{method:uncertainty}
The timing policy measures how strongly the belief supports a single state hypothesis. Belief entropy is
\[
\mathcal{H}(\mathcal{B}_{t+1})
=
-\sum_{k=1}^{j}w_k\log_2 w_k.
\]
Because the maximum entropy depends on the number of represented worlds, we normalize by $\log_2 j$ and define
\begin{equation}
\mathrm{Conf}(\mathcal{B}_{t+1})
=
1-\frac{\mathcal{H}(\mathcal{B}_{t+1})}{\log_2 j}.
\label{eq:compute_confidence}
\end{equation}
For $j=1$, we define $\mathrm{Conf}(\mathcal{B}_{t+1})=1$. The score approaches zero if the represented states have similar weights and approaches one if most of the belief weight lies on one state.

Given threshold $\tau\in[0,1]$, the robot initiates state verification if
\begin{equation}
\mathrm{Conf}(\mathcal{B}_{t+1})<\tau.
\label{eq:when_query}
\end{equation}
The threshold $\tau$ sets the confidence required to continue execution without further queries. A higher threshold requires a more concentrated belief and can increase the number of state confirmations. The timing criterion directly measures uncertainty in the state facts used for planning, so the robot can request verification even if the planner already identifies a single action.

\label{method:query_selection}
If verification is necessary, query selection aims to distinguish the remaining state hypotheses with fewer questions. Different facts can resolve different amounts of uncertainty, so the robot selects the fact with the largest expected entropy reduction. This criterion directs each query toward the uncertainty that prevents belief confidence from reaching $\tau$. The candidate set $\mathcal{C}(\mathcal{B})$ contains every fact that holds in at least one frontier state and is absent from at least one other state.
\[
\mathcal{C}(\mathcal{B})
=
\left\{
c\in\mathcal{F}
\;\middle|\;
0<\sum_{k:c\in s^k}1<j
\right\}.
\]
For candidate $c$, the truth value divides the belief into two subsets.
\[
\begin{aligned}
\mathcal{B}_{c}^{+}&=\{(s^k,w_k)\mid c\in s^k\},\\
\mathcal{B}_{c}^{-}&=\{(s^k,w_k)\mid c\notin s^k\}.
\end{aligned}
\]
Let $P(c)=\sum_{k:c\in s^k}w_k$ and $P(\neg c)=1-P(c)$. Entropy within each subset is computed after conditionally normalizing its weights. The expected posterior entropy of asking about $c$ is
\[
\mathbb{E}[\mathcal{H}\mid c]
=
P(c)\mathcal{H}(\mathcal{B}_{c}^{+})
+
P(\neg c)\mathcal{H}(\mathcal{B}_{c}^{-}).
\]
The selected query is
\begin{equation}
c^*
=
\arg\min_{c\in\mathcal{C}(\mathcal{B})}
\left[
P(c)\mathcal{H}(\mathcal{B}_{c}^{+})
+
P(\neg c)\mathcal{H}(\mathcal{B}_{c}^{-})
\right].
\label{eq:select_hypo}
\end{equation}
Equation~\ref{eq:select_hypo} maximizes expected entropy reduction because the entropy of the current belief is fixed across candidate facts. The robot recomputes the criterion after each response to select the next question from the remaining state hypotheses.

The selected predicate is converted into a binary state-verification query. For example, $c^*=\texttt{ripe}(\text{tomato}_1)$ produces the question \emph{Is tomato 1 ripe?} The response $y\in\{\texttt{true},\texttt{false}\}$ removes states inconsistent with the reported truth value.
\begin{equation}
\mathcal{B}
\leftarrow
\begin{cases}
\{(s^k,w_k)\mid c^*\in s^k\}, & y=\texttt{true},\\
\{(s^k,w_k)\mid c^*\notin s^k\}, & y=\texttt{false}.
\end{cases}
\label{eq:filter}
\end{equation}
The retained weights are renormalized, confidence is recomputed, and another fact is selected if confidence remains below $\tau$. The loop ends if the threshold is met or no differentiating fact remains. The robot then commits the maximum a posteriori state
\[
s_{t+1}^{K}
=
\arg\max_{s^k\in\mathcal{B}_{t+1}}w_k
\]
for subsequent symbolic planning. Commitment specifies the state against which the planner evaluates action preconditions and effects. Any remaining uncertainty is represented by the belief confidence at the end of verification.

Algorithm~\ref{alg:online_planning} summarizes planning and state verification. The belief update treats each response as hard evidence. Therefore, an incorrect response can remove the true state from the frontier. The oracle experiments evaluate the query policy with correct feedback, and the VLM and human experiments evaluate execution with responses from external experts.

\begin{algorithm}[t]
\caption{Belief-Guided State Verification and Planning}
\label{alg:online_planning}
\textbf{Input}\quad initial state $s_0^{K}$, confidence threshold $\tau$, step limit $T_{\max}$\\
\textbf{Output}\quad executed action sequence $\pi$
\BlankLine
$\mathcal{B}\gets\{(s_0^{K},1)\}\qquad t\gets0\qquad \pi\gets()$\\
\While{$t<T_{\max}$}{
    $a_t\gets$\Search{$\mathcal{B}$}\label{alg1_planning:search}\\
    \If{$a_t=\emptyset$}{
        \textbf{break}\tcp*{dead end}
    }
    execute $a_t$ and receive $o_{t+1}$\\
    $\pi\gets\pi\mathbin{\|}a_t$\\
    $\mathcal{B}\gets$\UpdateBelief{$s_t^{K},a_t,o_{t+1}$}\label{alg1_planning:belief_update}\\
    $q\gets\mathrm{Conf}(\mathcal{B})$\label{alg1_planning:compute_conf}\\
    \While{$q<\tau$}{
        $c^*\gets$\SelectBestHypothesis{$\mathcal{B}$}\label{alg1_planning:select_hypo}\\
        \If{$c^*=\emptyset$}{
            \textbf{break}\tcp*{no differentiating fact}
        }
        $y\gets$\QuerySource{$c^*$}\\
        $\mathcal{B}\gets$\FilterBelief{$\mathcal{B},c^*,y$}\label{alg1_planning:filter}\\
        $q\gets\mathrm{Conf}(\mathcal{B})$\\
    }
    $s_{t+1}^{K}\gets\arg\max_{s^k\in\mathcal{B}}w_k$\\
    $t\gets t+1$\\
}
\KwRet $\pi$
\end{algorithm}

\subsection{System Implementation}~\label{method:modules}
\begin{figure*}[t!]
\captionsetup{skip=0pt}
\centering
\includegraphics[width=0.95\linewidth]{figures/fig_dataflow.pdf}
\caption{System implementation of the belief-guided state-verification method. The KB shares task facts and action models across planning, sensing, and feedback. The PM retains action selection, while the FM and UI acquire external evidence about a selected symbolic fact.}
\label{fig:data_flow}
\end{figure*}

Figure~\ref{fig:data_flow} shows the modules that implement planning, perception, and state verification. The Knowledge Base (KB) provides the shared symbolic state and action model. The Planning Manager (PM) performs POMCP search, constructs and updates the reachable frontier, and invokes the feedback policy. Sensing and Perception (SP) supplies observations and numeric state estimates. The Feedback Manager (FM) formats the selected predicate and incorporates the response, while the User Interface (UI) presents state-verification questions during human interaction.

\label{method:KB}
The KB partitions information into domain knowledge $\mathcal{I}^{D}$, static structured information $\mathcal{I}^{S}$, and local information $\mathcal{I}^{L}$ obtained during execution.
\[
\mathcal{KB}=\mathcal{I}^{D}\sqcup\mathcal{I}^{S}\sqcup\mathcal{I}^{L}.
\]
Domain knowledge contains action schemas and task rules. Static information includes invariant facts and fixed map or robot parameters. Local information contains perceptual facts and numeric fluents that are updated during execution. SP maps raw sensor input to these task-level observations. For example, RGB-D sensing can update object pose and ripeness estimates, while the symbolic observation likelihood determines how those observations weight the frontier states.

\label{method:action_execution}
Each symbolic action invokes a robot skill. Actions such as $\texttt{navigate}(\text{robot},l_1,l_2)$ and $\texttt{pick}(\text{robot},\text{tomato}_1)$ specify task-level intentions, while an off-the-shelf motion planner such as MoveIt~\cite{chitta2012moveit} uses numeric fluents from the KB to generate low-level motion. This separation allows the feedback policy to operate on task-level facts without depending on a particular motion-planning implementation.

\label{method:FM}
The FM maps the selected predicate to a predefined question template and converts the response to a Boolean value. During human interaction, the tablet UI displays the camera view, highlights the referenced object with a bounding box, and presents simple response options. Participants answer questions about the displayed state fact, and the planner selects the next robot action.
