## 2. 기여 및 접근법 정리

### 2.1 When to query (Sec. 4.1.1)

- 액션 실행 후 가능한 후속 상태 집합(**frontier**) `F_{t+1}`을 만들고, 각 상태의 가중치를 `w_k ∝ T(s_k | s_t^K, a_t) · O(o_{t+1} | s_k, a_t)`로 계산.
- 정규화 엔트로피 기반 confidence:

  `Conf(B) = 1 − H(B) / log2(j)`

- `Conf(B) < τ` 이면 질의 트리거 (기본 τ = 0.8).
- 질의 후 confidence가 τ 이상이 되거나 구분할 사실이 없을 때까지 **반복 질의**.
- 이후 MAP 상태를 다음 계획용 상태 `s_{t+1}^K`로 확정.

### 2.2 What to query (Sec. 4.1.2)

- 질의 후보: belief 내 상태들 사이에서 참/거짓이 갈리는 원자 사실들.
- 각 후보 `q`에 대해 `P(q)·H(B_{q+}) + P(¬q)·H(B_{q−})`를 계산, **기대 사후 엔트로피가 최소인 사실** 선택 (= 정보 이득 최대).
- 답변(true/false)에 따라 불일치 상태를 제거하고 재정규화 (Eq. 5).

### 2.3 시스템 구현 (Sec. 4.2)

KB, Sensing & Perception, Planning Manager, Feedback Manager, UI의 모듈형 구조. 사실 → 질문 템플릿 변환(예: `ripe(t1)` → "Is tomato t1 ripe?")과 태블릿 UI(바운딩 박스 표시, 예/아니오 버튼)를 사용.

### 3.3 Ablation (Table 3)

- **타이밍 변경 (T1–T3)**: 랜덤/conformal/reward 타이밍은 성공률이 63–74%(T3의 WasteSorting 99% 제외)로 낮음. T3는 W.S.에서 99%이나 질의가 Ours 대비 125% 많음.
- **선택 변경 (S1–S2)**: confidence 타이밍을 유지하면 랜덤/보상 기반 선택도 성공률은 97.5–100%로 높음. 다만 질의 수가 Ours보다 27–66% 많음.
- 결론: *타이밍 → 성공률, 선택 → 질의 효율*.

### 3.4 Threshold 실험

- W.S.: τ ≥ 0.7에서 성공률 100%로 급등. τ = 1.0은 질의만 약 2배.
- T.H.: τ = 0.4에서 88.5%, 0.8에서 98%, 1.0에서 100%(질의 19.0회).
- τ = 1.0은 τ = 0.8 대비 질의 +91% / +107%, 성공률 개선은 +0 / +2pp.

### 3.5 인터뷰 (n = 5)

5명 중 4명이 Ours 선호. "현재 상태를 확인" (Ours) vs "다음 액션을 선택" (KnowNo)의 인지 부담 차이를 언급. 단, 반복 질의의 불편함도 보고됨(P3, P5).

## 4. 강점

1. **문제 설정이 명확하고 실용적이다.** "언제"와 "무엇"을 분리해 각각의 역할을 ablation으로 검증한 구조가 깔끔하다 (2×… 격자 형태의 Table 1이 특히 좋다).
2. **상태 불확실성에 기반한 질의라는 관점이 설득력 있다.** "액션 예측이 확신에 차 있어도 상태 추정이 틀릴 수 있다"는 지적은 KnowNo류의 한계를 정확히 짚는다. 실제 실패 분석에서도 이 주장을 뒷받침하는 사례가 나온다 (선행조건 미충족 상태에서 자율적으로 액션 선택 등).
3. **계산 비용이 낮다.** 질의 타이밍/선택을 belief에서 직접 계산하므로 LLM 호출이 필요 없고, 플래닝 시간이 약 1초 수준이다 (KnowNo/IntroPlan은 20–70초).
4. **세 단계의 평가 구성**: Oracle(대규모, 통제) → VLM(40 trial) → 사람(5명). 시뮬레이션 결과가 실물/사람에서도 유지되는지 확인하려는 설계가 좋다.
5. **ablation과 threshold sweep이 주장과 잘 정렬**되어 있다. 특히 "질의 수가 비슷해도 성공률이 다르다" (IntroPlan 8.96회/40% vs Ours 9.16회/98%)는 관찰이 인상적이다.
6. **사람 연구의 투명성**: IRB 승인, 참가자 순서 균형(Appendix C), 인터뷰 타임스탬프 제공, outlier 참가자(P3) 제외 분석까지 제시.
7. **부록의 재현성 정보**가 충실하다 (하이퍼파라미터, VLM 프롬프트 요약, trial 재사용 방식 명시).

## 5. 약점 및 우려 사항

### 5.1 방법론

1. **Belief가 시간에 걸쳐 누적되지 않는다.**
   매 스텝 `(s_t^K, a_t)`에서 생성한 **1-step frontier**로만 belief를 만들고, 이후 **MAP 상태로 collapse**한다 (Alg. 1, line 19). 즉 엄밀한 Bayes filter가 아니라 "one-step belief + MAP commit"에 가깝다. confidence가 τ를 넘었지만 MAP이 틀린 경우 오류가 이후 스텝으로 전파되며, 이전의 불확실성은 소실된다. Oracle에서 τ = 0.8일 때 98%(T.H.)에 머무르고 τ = 1.0에서 100%가 되는 점이 이 한계와 부합한다.

2. **답변이 항상 정확하다고 가정하는 하드 필터링 (Eq. 5).**
   불일치 상태를 **완전히 제거**하므로 잘못된 답변이 들어오면 복구할 수 없다. 실제로 VLM 실험에서 Ours의 실패 3건 모두가 VLM의 오답 때문이었다(각 도메인). 노이즈가 있는 응답자 모델(예: 응답 정확도를 반영한 soft update)이 필요하며, 이는 POMDP 관점에서도 자연스러운 확장이다.

3. **Confidence 정의의 해석 문제.**
   `Conf = 1 − H/log2(j)`는 j가 달라지면 동일한 분포라도 스케일이 달라진다. 예컨대 j = 2일 때 τ = 0.8을 만족하려면 H ≤ 0.2 비트, 즉 지배 상태의 확률이 약 0.97 이상이어야 한다. 이는 직관적인 "80% 확신"과 거리가 멀다. Threshold 실험에서 성공률이 계단식으로 변하는 점(W.S.에서 τ = 0.6 → 0.7에서 54% → 100%)도 τ가 도메인 모델의 belief 구조에 크게 의존함을 시사한다. 즉 **τ의 일반화 가능성**이 불분명하다.

4. **"When"이 decision-theoretic이 아니라 임계값 규칙이다.**
   질의 비용, 오답의 비용(되돌릴 수 없는 액션 등), 목표와의 관련성을 고려하지 않는다. 목표 달성과 무관한 사실이라도 엔트로피가 높으면 질의할 수 있다. 정보 가치(VOI) 기반 접근과의 비교/논의가 있었다면 좋았을 것이다. 본 방법이 모든 질의를 동일 비용으로 취급한다는 점은 한계로 명시될 필요가 있다.

5. **사후(post-action) 검증 중심.**
   belief는 액션 **실행 후** 결과에 대해 구성된다. 되돌릴 수 없는 실행(예: 잘못된 빈에 투입, 토마토 파손)에 대한 사전 확인이나 안전성 고려는 다뤄지지 않는다.

6. **전이/관측 모델 `T`, `O`의 출처가 불명확하다.**
   실물 로봇에서 `T(s' | s, a)`와 `O(o | s', a)`가 어떻게 정의·보정되는지(예: detector confidence → 관측 우도) 본문에서 충분히 설명되지 않는다. 방법의 핵심이므로 설명이 필요하다.

7. **확장성.**
   frontier 크기와 particle 용량(8,000)이 부록에 등장하는 것으로 보아 후보 상태 수가 큰 경우가 있다. 도메인 규모(객체 4개 안팎, 토마토 4개)는 작고, 객체/불확실 사실이 늘어날 때 frontier가 조합적으로 증가하는 문제가 논의되지 않는다.

8. **참신성의 범위.**
   엔트로피/정보 이득 기반 질문 선택 자체는 능동 학습, POMDP 정보 수집, 20 questions 류 연구에서 고전적인 아이디어다. 기여는 "심볼릭 frontier belief + POMCP + 상태 사실 질의"의 결합과 이를 LLM 기반 conformal 방식과 비교한 데 있다. 사람을 관측 제공자로 모델링한 POMDP 계열 연구(예: Rosenthal & Veloso), 역의미론 기반 도움 요청(Tellex et al.) 등 HRI의 질의 연구와의 위치 설정을 더 명확히 하면 좋겠다.

### 5.2 실험 설계의 공정성

1. **Baseline과 Ours의 플래너가 다르다(교란 요인).**
   Ours는 심볼릭 선행조건을 만족하는 액션만 POMCP로 탐색한다. 반면 KnowNo/IntroPlan은 LLM이 액션을 생성하며, 실패 분석에서 "선행조건 미충족 상태의 자율 액션 선택"이 주요 실패 원인으로 나타난다. 특히 **질의를 전혀 하지 않는 Ours(τ = 0.0)가 55% / 52%** 인데, 이는 KnowNo(48.5% / 43%)와 IntroPlan(51.5% / 40%)보다 **높거나 비슷하다**. 즉 baseline의 낮은 성공률 상당 부분이 "질의 전략"이 아니라 "플래너 차이"에서 올 수 있다. *KnowNo + 심볼릭 applicability filter* 같은 보정된 baseline이 있다면 질의 전략의 순수 효과를 더 잘 분리할 수 있다.

2. **KnowNo/IntroPlan은 본래 목적이 다르다.**
   이들은 지시문의 모호성(instruction ambiguity) 해소를 겨냥하며, 본 논문의 상태 불확실성 시나리오에 맞춰진 것이 아니다. 비교가 유의미하긴 하나, 승리의 크기를 해석할 때 이 점을 고려해야 한다.

3. **POMCP-Q와의 하이퍼파라미터 비교.**
   Ours는 γ = 0.2(시뮬레이션 깊이 약 4로 제한되는 매우 근시안적 설정)인 반면 POMCP-Q는 γ = 0.9 / 0.5이다. 각 방법에 대해 동일한 수준의 튜닝이 이루어졌는지 불분명하다. 또한 γ와 τ를 같은 평가 trial에서 선택한 것으로 보이며(τ = 0.8 선택 시 "same Ours trials" 재사용), 별도의 검증 세트가 없다.

4. **Oracle trial의 다양성이 제한적이다.**
   200 trial은 **5개 초기 구성 × 40회 반복**(Appendix A.1)이다. 통계적 독립성이 낮고 일반화 범위가 좁다.

5. **성공 trial에 한정한 비용 지표.**
   plan length, 시간 등은 "성공 trial 평균"이므로 성공률이 낮은 baseline(예: 25–50%)은 선택 편향이 있다. 지표 간 직접 비교 시 주의가 필요하다.

6. **통계 검정/신뢰구간 부재.**
   성공률 차이가 크긴 하지만, 특히 사람 평가(조건당 10 trial, 5명)에서는 참가자 간 군집(clustering)이 있으며 검정력/신뢰구간이 필요하다. 참가자도 소수, 연령대가 한정되어 있고(평균 26.4세), 방법에 대한 블라인드가 불가능하다.

7. **실물 실험의 baseline 범위.**
   실물(VLM/사람) 실험에는 KnowNo만 포함되고, Oracle에서 가장 강했던 POMCP-Q(그리고 IntroPlan)는 빠져 있다. 또한 VLM에 predicate별 판단 기준을 상세히 넣는 프롬프트 엔지니어링(Appendix B)이 Ours/KnowNo에 대칭적으로 적용됐는지 확인하기 어렵다. 질문이 한국어 템플릿이라는 점도 일반화 관점에서 언급할 만하다.

8. **Ablation의 교란.**
   T3/S2는 γ가 Ours와 다르고(0.9/0.5 vs 0.2), T2에서 **파싱 불가 출력 4건을 실패로 처리**했다. 또한 Fully-Random과 T1의 성공률이 두 도메인에서 모두 **정확히 73.50%로 동일**한데, 우연인지 시드 공유의 영향인지 설명이 있으면 좋겠다.

9. **"Ours가 질의를 더 많이 한다"는 사실의 해석.**
   KnowNo 대비 Ours는 질의 수와 때로는 질의 확률이 더 높다. 사람 연구에서 총 소요 시간이 비슷하고(180–190초), 인터뷰에서도 반복 질의에 대한 불편이 언급된다. 따라서 "사람의 부담이 적다"는 주장은 **질의당 인지 부담** 측면에 한정해야 하며, 총 부담은 더 정밀하게 측정(NASA-TLX 등)할 필요가 있다.

### 5.3 서술/편집상의 문제

- 초록에서 "We evaluate the framework in two robotic task domains..."와 "We evaluate the framework on two robotic tasks..."가 **중복**된다.
- 저자 소속에 **"Institution2"** 자리표시자가 남아 있다.
- Sec. 5.2.3에 **"Table ??"** (깨진 참조)가 있고, 본문에 threshold 결과 표가 없다.

- 5절 서두에 **"The planned human evaluation is designed for…"** 라는 계획형 표현이 남아 있다 (이미 수행된 실험).
- Fig. 5 캡션에 "asterisk marks a metric based on a single successful trial"이라 되어 있으나 그림에 별표가 보이지 않는다. Table 2의 `18.18±0.00` 같은 SD 0.00 값도 설명이 필요하다.
- Oracle은 "50 physical actions" 허용, 물리 실험은 "action limit 20"으로 상이한데 본문에서는 구분 설명이 부족하다.
- Sec. 5.2.1의 POMCP-Q 설명("These differences may contribute to…")은 **가설 수준의 추측**으로, 이를 직접 검증하는 실험은 없다.
- 일부 비율(예: T.H.에서 T3 질의 +32.71%)이 표의 반올림 값으로 계산 시 32.75%로 약간 차이가 난다. 미미하지만 비반올림 값에서 계산했음을 밝혀 두면 좋다.

## 7. 종합 평가

| 항목 | 평가 | 코멘트 |
|---|---|---|
| **문제의 중요도** | ★★★★☆ | 로봇의 질의 시점/내용 결정은 실용적으로 중요 |
| **참신성** | ★★★☆☆ | 개별 요소는 고전적이나, 심볼릭 belief + 상태 질의라는 결합과 LLM 기반 방식과의 대조가 의미 있음 |
| **기술적 건전성** | ★★★☆☆ | 아이디어는 명료하나 belief의 MAP collapse, 하드 필터링, τ 해석 등 이론적 허점 존재 |
| **실험의 엄밀성** | ★★★☆☆ | 규모와 단계적 설계는 좋으나 baseline 플래너 교란, 소규모 사람 평가, 통계 부재 |
| **명확성/완성도** | ★★★☆☆ | 구성은 좋으나 placeholder, 깨진 참조, 중복 문장 등 마무리 미흡 |
| **재현성** | ★★★★☆ | 부록의 파라미터/프롬프트 정보가 충실 |

**총평**: 상태 불확실성에 기반한 질의 설계라는 명확한 관점과, 타이밍/선택의 역할 분리를 깔끔한 ablation으로 보인 점이 가장 큰 강점이다. 다만 비교 baseline이 서로 다른 플래너 구조를 갖고 있어 성능 격차의 원인을 질의 전략으로만 귀속하기 어렵고, belief 갱신이 1-step + MAP 확정 + 하드 필터링에 의존해 **응답 노이즈에 취약**하다는 점이 실제 실패에서도 드러난다. 위 baseline 보정, 노이즈 응답 모델링, 통계적 보강, 그리고 편집상 오류 수정이 이루어진다면 훨씬 설득력 있는 논문이 될 것이다.
