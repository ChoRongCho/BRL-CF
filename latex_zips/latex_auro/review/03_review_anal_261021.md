# 세 논문 리뷰 통합 분석 및 수정 우선순위

작성일: 2026-10-21

분석 대상: [리뷰 1](01_paper_review.md), [리뷰 2](02_paper_review.md), [리뷰 3](04_stanford_review.md)

**세 리뷰는 문제 설정과 실험 구성을 긍정적으로 평가한다. 공통된 핵심 우려는 한 단계 frontier와 MAP 확정의 한계, 응답 오류 처리, POMCP-Q 비교의 공정성이다. 리뷰 1·2는 성능 격차의 원인 해석을, 리뷰 3은 질의를 탐색에서 분리한 설계와 belief 기반 정보 수집 연구와의 비교를 특히 강조한다.** 우선 원고의 주장과 방법 설명을 정확하게 맞추고, 기존 기록으로 확인할 수 있는 문제를 정리하는 것이 효과적이다. 리뷰에서 제안한 모든 방법 변형과 추가 실험을 수행할 필요가 있다는 뜻은 아니다.

이 문서는 리뷰를 그대로 수용하는 목록이 아니다. 타당한 지적, 확인이 필요한 추정, 논문의 범위를 넘어서는 제안을 구분한다. 현재 Introduction, Preliminaries, Method, 실험 본문 및 부록도 일부 대조했다. 원시 로그 재분석, 문헌의 서지 검증, 새로운 실험은 수행하지 않았다. 아래의 ‘확인 필요’ 항목은 아직 검증된 사실이 아니다.

## 0. 제출 전 반영 기준 — 저자 논의 반영

**리뷰의 모든 요구를 충족하는 것을 제출 조건으로 삼지 않는다. 정당성이 확인되지 않은 비판에 선제적으로 대응하기 위해 논문의 범위나 실험을 늘리지 않는다.** 현재 연구를 정확하게 전달하는 데 필요한 내용만 반영하고 제출한 뒤, 실제 심사에서 구체적인 근거와 함께 제기되는 요구는 그때 대응 가능성을 판단한다.

선제 반영 여부는 **그 내용이 없으면 독자가 현재 방법이나 결과를 잘못 이해하는가**를 기준으로 정한다. 리뷰가 제안했다는 사실만으로 추가 실험이나 새로운 한계 문단이 필요한 것은 아니다.

| 구분 | 처리 기준 | 현재 적용 |
|---|---|---|
| 제출 전 반영 | 실제 오류, 오해를 만드는 설명, 비교를 이해하는 데 필요한 설정 근거 | 깨진 참조·중복·용어 불일치, belief 설명의 정확성, reward 기반 gamma의 baseline 일치 명시 |
| 기존 결과로 이미 다룸 | 해당 우려를 평가와 실패 분석에서 관측·보고하고 있음 | VLM·사람 응답에서의 성능과 잘못된 응답에 의한 실패. 같은 문제를 미검증 상태처럼 다시 제기하지 않음 |
| 현 단계 선제 대응에서 제외 | 근거 없는 인과 추정, 잘못된 수치 해석, 현재 기여와 무관한 확장 요구 | 플래너 차이가 격차 대부분의 원인이라는 단정, gamma 차이 자체를 불공정으로 보는 주장, soft update·full-history belief 등을 제출 필수 조건으로 요구 |
| 실제 심사 후 판단 | 구체적인 문제 제기와 근거가 생겼을 때 대응 범위를 정할 항목 | 새 baseline, 추가 budget sweep, 오류 주입, workload 측정 등 |

아래의 상세 쟁점과 실험 후보는 검토 기록이다. **모두 제출 전에 완료해야 하는 작업 목록이 아니다.** 실제 오류가 발견되면 바로잡되, 예상 가능한 모든 비판을 논문 안에서 먼저 방어하지 않는다.

## 1. 세 리뷰의 공통점과 평가 차이

| 항목 | 리뷰 간 관계 | 원고 수정에서의 의미 |
|---|---|---|
| 문제 설정과 실험 구성 | 세 리뷰 모두 긍정적 | 현재 문제와 평가 구조를 유지하고 각 비교의 근거를 명확히 함 |
| 주요 결과 | 세 리뷰 모두 높은 성공률과 ablation의 의미를 인정 | 관측 결과와 그 원인에 대한 주장을 분리 |
| 참신성 | 리뷰 1·2는 고전적 요소의 결합을 강조하고, 리뷰 3은 구조화된 frontier와 질의 분리를 강점으로 평가 | 새로운 entropy 이론이나 particle 근사 기법이라는 주장 없이 설계의 기여를 설명 |
| Belief 표현 | 세 리뷰 모두 한 단계 frontier와 MAP 확정의 한계를 지적 | 현재 belief 사용과 full-history tracking을 구분하고, 질의 후 MAP 선택의 설계 이유를 함께 설명 |
| 비교의 공정성 | 리뷰 1·2는 planner·질의 형식·gamma 차이, 리뷰 3은 compute 및 search space 차이를 강조 | 시스템 비교와 통제된 구성요소 비교를 구분하고 budget 정의를 명시 |
| 응답 오류 | 세 리뷰 모두 hard filtering의 취약성을 지적 | 현 방법의 가정과 관측된 실패를 연결 |
| 모델 출처와 확장성 | 세 리뷰 모두 T/O 설명과 큰 상태 공간에서의 처리를 문제 삼음 | 모델 출처, frontier 구성·제한 방식을 짧게 설명하고 상세 설정은 코드로 연결 |
| 인간 실험 | 세 리뷰 모두 소표본 통계 문제를 지적하며, 리뷰 1·2는 workload 미측정을 강조 | 인터뷰의 긍정적 평가를 일반적 인지 우수성으로 확대하지 않음 |
| 관련 연구 | 리뷰 1·2는 HRI·정보 이득 연구, 리뷰 3은 belief-dependent planning과 predicate verification 연구를 구체적으로 제안 | 후보 문헌의 실재·관련성을 먼저 검증하고 핵심 차이를 정리 |
| 편집 상태 | 리뷰 1·2에서 구체적 오류를 열거하고, 리뷰 3은 전반적 명료성을 긍정 평가 | 편집 오류와 기술적 쟁점을 별도로 처리 |

리뷰 1은 baseline 보강을 특히 강하게 요구하고, 리뷰 2는 조건부 Weak Accept로 평가한다. 리뷰 3은 한계 설명과 모델 명세를 보강하고 계산 예산을 맞춘 비교 또는 rho-POMCP 계열 비교를 추가한다면 수용을 지지한다고 한다. 이 평가 문구는 실제 심사 결과나 채택 가능성을 예측하는 근거로 삼지 않는다. 리뷰들의 독립성도 확인되지 않았으므로, 의견의 중복을 독립적인 세 표로 해석하지 않는다.

## 2. 논문의 중심 주장을 어떻게 유지할 것인가

### 2.1 Baseline 비교는 시스템 수준의 결과다

현재 결과는 **평가한 조건에서 제안 시스템의 성공률이 비교 시스템보다 높다**는 주장을 뒷받침한다. KnowNo/IntroPlan과는 플래너와 질의 형식도 다르므로, 이 차이 전체가 질의 시점만으로 발생했다고 설명하면 방어하기 어렵다.

따라서 실험의 역할을 다음과 같이 구분한다.

| 평가 | 직접 보여주는 내용 | 이 평가만으로 단정하기 어려운 내용 |
|---|---|---|
| Baseline 비교 | 서로 다른 질의 시스템의 종합 성능 | 성능 차이 전체가 timing 때문에 발생했다는 인과적 설명 |
| Timing ablation | 제안 프레임워크 내에서 질의 시작 기준을 바꾸었을 때의 결과 | 모든 플래너와 모든 질의 형식에서 timing의 효과가 같다는 주장 |
| Selection ablation | 정해진 trigger 및 반복 검증 조건에서 선택 기준에 따른 질의 수 차이 | Selection이 일반적으로 성공률과 무관하다는 주장 |
| VLM·사람 평가 | 정답 응답만 사용하는 조건을 넘어선 물리적 실행 결과 | 사람의 workload 감소 또는 상태 질문의 보편적 우수성 |
| 인터뷰 | 참여자가 질문과 행동의 실행 범위를 어떻게 해석했는지 | 측정하지 않은 인지 부담이나 일반 사용자 전체의 선호 |

리뷰가 긍정적으로 언급한 ‘상태 질문이 행동 질문보다 쉽다’도 그대로 논문의 중심 주장으로 가져오지 않는다. **우리 논문은 두 질문 형식 중 어느 것이 사람에게 더 우수한지 검증한 연구가 아니다.** 인터뷰는 관측된 실패와 참여 경험을 해석하는 자료로 사용한다.

### 2.2 기존 ablation을 먼저 활용할 수 있다

세 리뷰는 비교 조건 보강을 제안하지만, 현재 실험에도 활용할 수 있는 통제 비교가 있다.

- T1과 Ours는 entropy gain selection과 기본 discount factor를 공유한다. 이 비교를 timing 효과의 주요 근거로 사용할 수 있다.
- S1과 Ours는 confidence timing과 기본 discount factor를 공유한다. 이 비교를 selection에 따른 질의 수 차이의 주요 근거로 사용할 수 있다.
- Fully-Random과 S1은 random selection을 유지하면서 timing을 바꾸는 비교다.
- T2는 질의 시작뿐 아니라 반복 질의를 종료하는 기준도 다르다. 따라서 ‘시작 시점 하나만 바꾼 비교’라고 설명하면 부정확하다.
- T3와 S2는 reward 기반 baseline의 gamma를 유지한 대안 정책 비교다. 이 설정을 불공정으로 취급하지 않으며, 다른 모든 변수를 고정한 단일 요소 비교와 구분해서 설명한다.

다만 설정표의 일치가 실행 구현의 완전한 통제를 보장하지는 않는다. 강하게 주장하려면 실제 구성 파일과 반복 검증 규칙도 확인해야 한다.

### 2.3 No-query 결과의 의미

Ours의 무질의 조건은 WasteSorting 55%, TomatoHarvesting 52%이며, 기본 설정은 100%, 98%다. 따라서 제안 시스템 내부에서는 질의가 있는 설정에서 각각 **45, 46 percentage points** 높은 성공률을 관측한다.

이 결과는 질의가 없는 제안 시스템보다 현재 질의 정책을 사용하는 시스템의 성능이 높다는 근거다. 다만 이 차이는 timing, selection, 응답 반영을 포함한 질의 기능 전체의 차이다. Timing만의 순수 효과는 아니다.

또한 무질의 Ours가 KnowNo/IntroPlan보다 비슷하거나 높은 성능을 보인다는 사실만으로 ‘baseline 격차의 상당 부분이 플래너 차이 때문’이라고 정량적으로 결론 낼 수 없다. 이는 교란 가능성을 제기하는 근거이며, 기여도를 분해한 결과는 아니다. 각 baseline의 무질의 조건도 아직 이 두 수치에 포함되어 있지 않다.

## 3. 쟁점별 대응 판단

### 3.1 Belief와 MAP 선택 — 질의 후 계획 상태를 정하는 설계

**우리 방식도 belief를 사용한다. 설명할 차이는 belief의 존재가 아니라 다음 단계로 전달하는 정보다.** 실행 후 가능한 상태들과 정규화된 가중치가 weighted belief를 구성하며, 그 분포에서 confidence와 질문을 계산한다. 이후 선택한 MAP 상태를 다음 symbolic planning state와 후속 frontier 구성의 기준으로 사용한다.

일반적인 재귀적 belief tracking은 여러 상태의 확률을 다음 단계로 전달해 분포 전체에서 다음 belief를 계산한다. 현재 방법은 모든 잔여 가설을 같은 방식으로 이월하지 않는다. 따라서 실행 이력 전체의 불확실성을 그대로 유지한다고 읽히는 표현은 조정하되, belief라는 명칭을 버리거나 full-history filtering으로 방법을 바꿀 필요는 없다.

#### MAP 선택의 설계 이유 — 저자 설명

1. **외부 응답을 신뢰해 상태를 확인한다.** 응답을 확인된 정보로 받아들여 그 응답과 일치하지 않는 가설을 제거한다. 이 가정은 hard filtering에 직접 반영된다.
2. **잔여 가설에서 후속 후보가 계속 확장되는 것을 제한한다.** 모든 후보 상태를 다음 단계의 출발점으로 계속 유지하는 대신, MAP 상태를 기준으로 후속 frontier를 구성한다. 이는 후보 누적과 계산 부담을 제한하려는 설계 목적이며, 실제 계산량 감소의 정도를 별도로 정량화했다는 뜻은 아니다.
3. **불확실성이 큰 경우에는 확정 전에 질문한다.** 예를 들어 두 상태가 50%–50%라면 normalized entropy confidence가 낮아 질의를 유발한다. 구분 가능한 사실에 대해 응답을 받아 후보를 줄인 뒤, confidence 기준을 만족하면 MAP 상태를 다음 계획의 기준으로 사용한다.

핵심 순서는 **행동 후 belief 구성 → 불확실하면 질의 및 응답 반영 → MAP 상태 선택 → 다음 symbolic planning**이다. 불확실한 분포에서 아무 확인 없이 단일 상태를 선택하는 방법으로 설명하면 설계 의도가 빠진다. 알고리즘에는 구분 가능한 질문 후보가 없을 때도 질의 루프를 종료하는 조건이 있으므로, 모든 종료에서 confidence 기준 충족이 보장된다고 서술하지 않는다.

97%와 3%처럼 잔여 가설이 있는 경우, 3% 상태가 수학적으로 불가능하거나 모든 과업에서 의미 없다는 뜻은 아니다. **설정한 confidence 기준을 만족하면 잔여 가설을 다음 계획 단계로 전달하지 않고 MAP 상태를 채택한다는 운영상의 선택**이다. Confidence threshold는 최대 상태 확률 자체가 아니므로 ‘tau=0.8이면 확률 80% 상태를 선택한다’고 설명하지 않는다.

#### 제출 전 설명에 반영할 범위

- 현재 실행 결과를 검증하는 weighted frontier belief.
- 질의 후 다음 symbolic planning에 사용하는 MAP knowledge state.
- Action value를 추정하는 POMCP search-tree particles.

이 세 요소와 MAP 선택의 목적을 기존 설명 안에서 짧게 연결한다. **잔여 불확실성을 버리는 한계만 부각하거나, full-history belief가 없으므로 방법이 잘못되었다는 리뷰 해석을 받아들이지 않는다.** MAP 선택은 우리의 설계 선택이며 symbolic planning에서 수학적으로 반드시 요구되는 조건이라는 주장도 하지 않는다.

리뷰의 ‘POMDP가 아니라 query wrapper’라는 표현 역시 그대로 수용하지 않는다. 어떤 belief를 어떤 의사결정에 사용하는지 구체적으로 설명하면 된다. 이를 이유로 새로운 belief 이월 알고리즘이나 추가 ablation을 제출 전 필수 과제로 만들지 않는다.

### 3.2 Hard filtering — 취약성과 기존 평가를 함께 해석

Hard filtering이 오답으로 정답 상태를 제거할 수 있다는 지적 자체는 타당하다. **그러나 그 취약성이 있다는 사실과, 현재 논문이 실제 응답 오류를 평가하지 않았다는 주장은 다르다.** 우리는 이미 정답 응답만 사용하는 시뮬레이션을 넘어 VLM과 사람의 실제 응답으로 실험했고, 응답 오류로 발생한 실패도 보고했다.

| 응답 조건 | Ours의 WasteSorting 성공 | Ours의 TomatoHarvesting 성공 | 보고된 응답 오류 실패 |
|---|---|---|---|
| VLM | 37/40, 92.5% | 37/40, 92.5% | 각 도메인의 세 실패가 VLM 응답 오류와 연결됨 |
| 사람 5명 | 9/10, 90% | 10/10, 100% | WasteSorting의 한 실패가 보이지 않는 물체에 대한 잘못된 확인 이후 발생 |

따라서 **실제 응답 오류가 가능한 조건에서도 높은 성공률을 관측했고, 잘못된 응답으로 실패할 수 있다는 점도 기존 실패 분석에서 드러났다.** Hard filtering을 사용한다는 이유만으로 현 방법의 실험적 검증이 빠져 있다고 취급하지 않는다. 사람 다섯 명의 평가는 해당 실험 조건에서의 증거이며, 모든 응답 오류율이나 사용자 집단에 대한 강건성을 보장한다는 주장은 하지 않는다.

제출 전에는 현재 update 규칙과 실패 분석이 명확하게 연결되는지 확인하면 된다. 이미 설명되어 있다면 같은 취약성을 별도의 긴 방어 문단으로 반복할 필요가 없다. **Soft update, 오류 주입 실험, 재확인 정책은 현 단계의 선제 수정 대상에서 제외한다.** 실제 심사에서 기존 평가로 답하지 못하는 구체적인 요구가 나올 때 그 필요성을 판단한다.

또한 리뷰의 ‘오답이면 항상 Conf=1’ 또는 ‘이후 영원히 복구 불가’는 그대로 받아들이지 않는다. 여러 상태가 응답과 일치하면 confidence가 반드시 1이 되는 것은 아니며, 이후 복구 가능성은 전이와 belief 구성에 달려 있다.

### 3.3 POMCP-Q 및 reward 기반 조건의 공정성

**T3·S2의 gamma는 reward 기반 baseline과 맞춘 설정이라는 저자의 설명을 반영한다.** 임의로 다른 gamma를 부여한 불공정한 실험으로 취급하지 않는다. 원고에는 해당 baseline 설정을 유지했다는 근거를 짧게 명시하면 된다. 다만 다른 모든 변수를 고정한 단일 요소 비교와 baseline 설정을 유지한 대안 정책 비교는 구분한다.

리뷰가 제기한 쟁점은 discount factor, action branching, search budget, query의 trial-limit 소모다. 서로 얽혀 있어 하나의 원인으로 단정하면 안 된다. 리뷰 3은 특히 계산 예산을 맞춘 비교를 요구한다.

현재 파라미터 표는 Ours와 POMCP-Q 모두 decision당 POMCP simulations를 100회로 기재한다. 따라서 이미 명목상 simulation count는 같다. 그러나 action branching, 실제 도달 깊이, query decision 수가 달라 step당·trial당 실제 연산량이나 시간까지 같다는 뜻은 아니다. 반대로 시간이 더 길다는 사실만으로 POMCP-Q에 더 적은 예산을 주었다고 결론 낼 수도 없다.

Simulation 수를 맞추는 비교는 동일한 rollout 횟수에서의 동작을 보여주고, wall-clock time을 맞추는 비교는 같은 시간 안에서의 성능을 보여준다. 목적이 다르므로 어느 단위의 budget을 비교했는지 먼저 밝힌다. 추가 time-matched 평가를 한다면 같은 하드웨어, 시간 측정 범위, 질의 시간 포함 여부도 정의해야 한다.

기존 자료로 먼저 확인할 항목은 다음과 같다.

| 확인 항목 | 필요한 근거 | 확인 후 할 수 있는 설명 |
|---|---|---|
| Gamma 설정 | Reward 기반 baseline과 동일하게 설정했다는 저자 설명 및 구성 파일 | Baseline 설정을 유지한 비교임을 명시. Sweep 결과나 별도 최적화는 기록 없이 주장하지 않음 |
| Trial limit 실패 | 종료 이유와 실제 query/action 수 | 전체 실패 중 decision budget 소진의 비중 |
| Search allocation | Action별 visits와 value 기록 | 특정 후보 평가에 탐색이 편중되었는지 |
| 실제 계산 예산 | 설정된 simulations, 실행 decision 수, 측정 시간과 하드웨어 | Decision당 같은 설정과 trial당 다른 실제 비용을 구분 |
| T3의 trigger | Trigger 직전 confidence, query/physical value | 높은 confidence에서 질문하거나 낮은 confidence에서 질문을 놓친 실제 사례 |
| Reward 정의 | Domain 설정 파일 | Action reward, 실패·반복 행동 penalty의 실제 값 |

이 자료가 없거나 설명 후에도 공정성 우려가 남으면 gamma와 simulation budget을 바꾼 추가 평가를 고려한다. 먼저 확인하지 않고 ‘POMCP-Q가 더 큰 action space 때문에 실패했다’거나 ‘gamma가 원인이다’라고 확정하지 않는다.

### 3.4 Timing과 selection에 대한 결론의 범위

리뷰 2는 정답 응답을 받으며 confidence 기준까지 반복하는 구조가 selection별 성공률 차이를 작게 만들 수 있다고 지적한다. 중요한 해석이다.

현재 결과에서 유지할 수 있는 결론은 다음과 같다.

> 정답 응답과 반복 검증을 사용하는 평가 조건에서, 질의 timing을 바꾸면 성공률 차이가 나타나며 confidence timing을 고정한 selection 비교에서는 주로 질의 수 차이가 나타난다.

‘Selection은 성공률에 영향을 주지 않는다’는 일반 명제로 확대하지 않는다. 다만 이 현상이 설계와 연결된다고 해서 ablation이 무의미해지는 것도 아니다. **동일한 종료 조건에 도달하는 데 몇 번의 질문이 필요한지**는 실제 평가할 가치가 있다.

정답 응답 및 결정적인 fact truth value라는 가정에서는 다음 관계가 성립한다.

`H(S) − E[H(S | Y)] = I(S; Y) = H(Y) = H_b(P(q))`

여기서 `Y`는 fact q의 참/거짓 응답이다. 따라서 현재 expected entropy gain selection은 `P(q)`가 0.5에 가까운 분할을 선호한다. 새로운 정보 이론적 기여를 주장하기보다 선택 기준의 의미를 설명하는 데 사용할 수 있다. 이 관계를 이유로 task reward까지 최적화한다고 설명해서는 안 된다.

### 3.5 Confidence, threshold 및 모델 출처

다음 세 질문을 분리해서 대응한다.

- **수치의 의미**: normalized entropy confidence 0.8은 정답 확률 80%라는 뜻이 아니다.
- **선택 절차**: tau와 gamma를 언제, 어떤 trial로 정했는가.
- **모델의 근거**: transition과 observation probabilities를 어디서 가져왔는가.

같은 Ours batch를 재사용했다는 사실만으로 평가 데이터에 맞춰 threshold를 튜닝했다고 확정할 수는 없다. 설정 선택 기록이 필요하다. 별도 검증 세트가 없었다면 사후에 있었다고 설명하지 않는다.

전이·관측 확률표 전체를 부록에 복원할 필요는 없다. 다만 **모델 값의 출처와 정하는 방식, detector confidence와 likelihood의 관계**는 실제 구현을 확인해 본문 또는 부록에 짧게 남길 가치가 있다. 구체적인 값은 코드·설정 파일에 연결할 수 있다. 현재 문서에는 이 출처를 단정할 근거를 추가하지 않는다.

### 3.6 인간 실험과 통계

인간 결과는 다섯 명의 반복측정 결과다. 조건당 10 trials를 서로 독립적인 10명의 관측처럼 취급하면 안 된다.

- 전체 참여자 결과를 주 결과로 유지.
- P3 제외 결과는 관측된 긴 응답의 영향을 보는 추가 분석으로 구분.
- 정성적 인터뷰를 workload 감소의 정량적 증거로 해석하지 않음.
- 성공 trial 비용은 성공한 trial에 한정된 조건부 평균이라는 점을 유지.
- Trial duration과 workload, query당 응답 시간과 고민 시간을 같은 개념으로 취급하지 않음.

두 리뷰가 제안한 Wilson interval을 조건당 pooled human trials에 기계적으로 붙이는 것만으로 반복측정 문제를 해결할 수 없다. 추론 통계를 추가한다면 참여자를 분석 단위 또는 군집으로 고려해야 하며, 참여자 수가 다섯 명이라는 제한도 남는다. 기존 SD 그림을 다시 복잡하게 만드는 것을 우선 과제로 삼지 않는다.

NASA-TLX를 지금 추가하는 것은 편집 수정이 아니라 새로운 측정이다. 기존 실험 당시 측정하지 않은 workload를 사후에 수집해 당시의 측정치처럼 보고할 수 없다. 현재 논문은 인터뷰의 범위에 맞게 주장하면 된다.

### 3.7 질의를 action search에서 분리한 설계와 추가 비교군

리뷰 3에서 새로 강조한 부분이다. Ours는 physical action search와 외부 질의 결정을 분리한다. 리뷰는 이를 search space를 줄이는 실용적 설계로 평가하는 동시에, future query와 physical action을 함께 최적화하지 않는 선택이라는 점도 설명할 것을 요구한다.

유지할 수 있는 주장은 **상태 belief를 이용해 언제·무엇을 확인할지 정하고, 행동 선택은 POMCP가 담당하도록 구성했다**는 것이다. 현재 결과만으로 전역 최적성, 일반적인 search explosion의 해소, 정보 수집을 planning 안에서 처리하는 모든 방식에 대한 우위를 주장하지 않는다. 동일한 설계 선택의 장점과 한계를 함께 쓰면 된다.

리뷰 3의 비교 제안은 두 방향이다.

| 비교 방향 | 리뷰에서 제시한 후보 | 확인할 질문 |
|---|---|---|
| Belief-dependent utility를 planning 안에서 최적화 | rho-POMCP, entropy 또는 information-gain reward, EFE 관련 접근 | 같은 belief와 query action·응답 모델을 사용했을 때 질의 결정을 분리하는 효과가 남는가 |
| Task relevance를 기준으로 불확실성 축소 | STRUG로 지칭한 연구 및 관련 방식 | 전체 entropy를 줄이는 질문과 task에 중요한 사실을 확인하는 질문의 차이가 무엇인가 |

이 후보들의 실제 명세와 원 논문은 아직 확인하지 않았다. 리뷰의 이름만으로 정확한 알고리즘이나 직접 구현 가능한 baseline이라고 확정하지 않는다. 특히 `−H(b′)`와 `H(b)−H(b′)`를 매 단계 reward로 사용하는 설계는 horizon과 discounting에 따라 목적이 달라질 수 있으므로 같은 방법처럼 취급하지 않는다.

새 baseline을 고려한다면 belief 표현, physical action 모델, 질의 후보와 응답 정확도, task reward와 information reward의 결합 방식, query cost, 종료 조건, 계산 budget을 명시해야 한다. 단순히 entropy reward를 하나 넣었다고 더 공정한 비교가 자동으로 완성되지는 않는다.

따라서 **관련 연구의 위치를 확인하는 작업은 우선순위를 높이되, rho-POMCP 구현을 바로 필수 과제로 확정하지 않는다.** 현재 논문의 핵심이 query-action 통합 계획보다 질의 분리가 유리하다는 주장으로 확대된다면 직접 비교의 필요성이 커진다. 현재 설계의 실용적 결과를 보고하는 범위라면 기여와 한계의 설명부터 정확히 한다.

### 3.8 Frontier의 실제 구성과 추가 관련 연구

리뷰 3은 frontier를 어떻게 생성하고 여러 fact의 효과를 어떻게 조합하며, 불가능한 조합을 어떻게 제외하는지가 불명확하다고 지적한다. 이는 큰 capacity 값이 있다는 확장성 우려와 연결되지만, 먼저 **구현을 이해하기 위한 설명 부족**의 문제다.

- 실제 구현이 모든 successor를 열거하는지, sampling으로 일부를 구성하는지 확인.
- Multi-fact effect와 서로 배타적인 결과를 처리하는 방식 확인.
- Transition sampling budget과 frontier/search-node capacity의 역할 구분.
- Budget이나 capacity 때문에 상태가 생략되는 경우와 confidence 계산의 관계 확인.
- Candidate fact 수와 fact별 posterior 계산 비용을 기존 기록에서 확인 가능한지 점검.

이 설명을 위해 frontier sampling을 새로운 알고리즘 기여로 격상하거나 삭제한 알고리즘 부록을 복원할 필요는 없다. 실제 동작을 짧게 설명하고 상세 구현에 연결하면 된다.

리뷰 3은 VAP-TAMP, `BKLV A`, RoVLaP라는 이름의 연구도 제시한다. 해당 리뷰 스스로 ‘제공된 요약에 기반한 비교’라고 밝히므로, 제안 방법과의 우열이나 세부 차이를 검증된 문헌 사실로 옮겨 쓰면 안 된다. 특히 `BKLV A`는 정확한 표기부터 확인해야 한다. 각 후보의 원 논문을 확인한 뒤 다음 네 축으로 정리한다.

1. 무엇에 대한 불확실성을 어떤 belief로 표현하는가.
2. 언제 추가 관측이나 외부 질문을 수행하는가.
3. 무엇을 관측·질문할지 어떤 기준으로 정하는가.
4. 질문 응답을 이후 계획과 실행에 어떻게 반영하는가.

‘Predicate verification을 한다’는 공통점만으로 동일한 문제를 푼다고 결론 내리지 않으며, 반대로 entropy를 사용한다는 이유만으로 우리 기여가 자동으로 구별된다고 설명하지 않는다.

| Gamma=0.9이면 탐색 깊이가 약 50이므로 100 simulations가 부족함 | Discount cutoff만 보면 깊어지지만 maximum depth 20도 적용된다. 실제 최대 깊이를 약 50으로 설명하는 것은 잘못이다. Budget 부족 가능성은 별도 검증 대상이다. |
| Selection 변형의 질의가 Ours보다 27–66% 많음 — 리뷰 1 | 증가율과 감소율의 분모를 혼동했다. 표의 반올림 값으로 보면 S1/S2의 증가는 W.S. 약 94%/191%, T.H. 약 38%/66%다. 원고의 Ours 감소율 48.54%, 65.64%, 27.72%, 39.92%와 구분한다. 정확한 보고는 반올림 전 값으로 계산한다. |
| Tau=0.8을 j=2–8에서 특정 p_max 범위와 대응 | Binary 예시는 가능하지만 j>2에서는 나머지 확률이 어떻게 분포하는지에 따라 entropy가 달라진다. j와 tau만으로 p_max를 하나로 정할 수 없다. |
| True transition/observation model을 쓰면 belief가 구성상 calibrated임 | MAP 근사, sampling/truncation, 모델과 현실의 차이가 있어 자동으로 보장되지 않는다. 실제 정확도와 confidence의 관계는 별도 분석 대상이다. |
| Same batch 재사용은 곧 test-set tuning임 | 재사용 사실과 설정 선택 절차는 다르다. 실험 기록을 확인한 뒤 판단한다. |
| 5개 구성 × 40회이므로 trials가 통계적으로 독립적이지 않음 | 구성의 다양성이 작다는 지적은 타당하다. 다만 같은 구성의 독립 seed 반복이라는 이유만으로 모든 trial이 종속된다고 단정할 수는 없다. 어떤 모집단으로 일반화하는지와 반복 구조를 설명한다. |
| Fully-Random과 T1의 같은 성공률은 반복 검증 구조 때문임 | 가능한 설명이지만 aggregate 성공률의 일치만으로 원인을 확정할 수 없다. Trial별 성공 여부와 실패 경로를 대조해야 한다. |
| Soft update에서는 Conf가 1이 되지 않으므로 비용 인식형 정지가 필수임 | 현재 기본 정지는 Conf가 tau=0.8에 도달하는 조건이다. Conf가 정확히 1이 될 필요는 없다. 새로운 정지 규칙은 update 설계에 따라 판단한다. |
| VLM top-5 log probabilities를 KnowNo만 사용함 | 외부 VLM 응답 설정과 KnowNo의 candidate-scoring model을 구분해야 한다. 확률을 기록한다는 사실만으로 어느 모듈에서 사용했는지 알 수 없다. |
| 모델이 달라졌는데 KnowNo calibration threshold가 같으므로 오류임 | GPT-4o 후보 점수와 외부 Gemma 피드백은 다른 역할이다. Calibration score를 생성하는 모델이 바뀌었는지를 먼저 확인해야 한다. 같은 숫자만으로 복사 오류나 coverage 위반을 단정하지 않는다. |
| 성공률 개선량을 질의 수로 나누어 방법의 효율을 비교 | 성공률은 전체 trial, 현재 mean query count는 성공 trial 기준이다. 서로 다른 분모를 바로 결합한 비율은 해석하기 어렵고, 질의당 인과적 이득도 아니다. |
| 100.0%와 98.00% 혼재는 무조건 수정해야 함 | 100.00만 100.0으로 줄인 현재 표기는 저자의 명시적 편집 선택이다. 자동으로 일괄 통일하지 않는다. |
| POMCP-Q의 더 긴 planning time은 불공정한 compute budget을 의미함 — 리뷰 3 | 같은 simulation count에서도 branching과 연산량 때문에 시간이 달라질 수 있다. 명목 budget, 실제 사용량, 시간 측정 단위를 구분해서 확인한다. |
| rho-POMCP는 반드시 더 공정한 baseline임 — 리뷰 3 | 가까운 비교 후보라는 제안은 중요하지만, belief·reward·query 모델과 budget을 맞추는 절차가 필요하다. 리뷰의 평가만으로 공정성이 입증되지는 않는다. |
| 인터뷰가 user-centered advantages를 검증함 — 리뷰 3 | 참여 경험에 대한 정성적 근거는 있으나 workload나 인지적 우수성의 정량적 검증으로 확대하지 않는다. |
| 그림 error bar와 별표를 복원해야 함 | 두 리뷰의 핵심 편집 지적은 실제 그림과 캡션의 불일치다. 삭제된 error bar를 되살리기보다 현재 표시와 맞지 않는 캡션을 정리한다. |

제안된 관련 연구 저자와 인용도 정확한 논문을 확인한 뒤 사용한다. 리뷰의 예시 이름만으로 참고문헌을 추가하지 않는다. 이 원칙은 리뷰 3의 rho-POMCP/EFE, STRUG, VAP-TAMP, `BKLV A`, RoVLaP에도 동일하게 적용한다.

## 6. 실행 순서와 작업 범위

이 절은 가능한 작업을 분류한 기록이다. 제출 전 필수 범위는 0절의 기준으로 제한한다. 기존 기록 분석과 새 실험 후보 전체를 먼저 완료한 뒤 제출한다는 계획으로 해석하지 않는다.

### 1단계 — 새로운 실험 없이 원고의 정확성부터 정리

- [ ] 깨진 참조, W/Q 표기, 계획형 표현, abstract 중복, 실제 그림과 맞지 않는 캡션 정리.
- [ ] Introduction의 belief 설명을 Method와 일치시킴.
- [ ] 시스템 비교와 구성요소 ablation의 근거를 분리.
- [ ] 정답 응답·반복 검증 조건 안에서 timing/selection 결과를 해석.
- [ ] MAP 확정의 설명을 실제 방법과 맞추고, hard filtering의 응답 오류는 기존 VLM·사람 실패 분석에서 이미 다룬 범위를 확인. 중복 한계 문단은 추가하지 않음.
- [ ] Workload, 사람의 판단 난이도, 선호에 대한 주장을 측정 범위에 맞춤.
- [ ] 질의를 action search에서 분리하는 설계를 장점과 한계가 있는 선택으로 설명.
- [ ] 리뷰 3의 관련 연구 후보를 검증한 뒤 정보 수집 planning과의 위치를 짧게 정리.

이 단계는 추가 연구를 약속하는 작업이 아니라 현재 결과를 정확하게 전달하는 작업이다.

### 2단계 — 기존 설정과 로그에서 근거 확보

- [ ] Reward 기반 gamma가 baseline과 동일하다는 설정 근거를 명시. Tau 선택 과정은 현재 원고에서 그 절차를 주장하는 경우 기록과 대조.
- [ ] POMCP-Q의 decision-limit 소진 실패 수 확인.
- [ ] 동일한 simulation 설정과 실제 trial별 계산 비용을 구분하고 time-matched 비교의 필요성 판단.
- [ ] T3의 누락 trigger와 불필요한 trigger를 confidence·value·visit 기록으로 대조.
- [ ] KnowNo/IntroPlan의 입력 상태 정보와 oracle 응답 규칙 확인.
- [ ] T/O 모델의 출처 및 reward 정의 확인.
- [ ] Frontier의 실제 생성 방식, multi-fact 효과 및 invalid combination 처리 확인.
- [ ] Frontier·candidate fact 크기, capacity 도달 및 truncation 여부를 기존 기록에서 확인 가능한지 점검.
- [ ] VLM 프롬프트에서 공통 정보와 질의 형식에 따라 다른 정보를 구분.

이 단계에서 기록이 없으면 없다고 남긴다. 설명을 맞추기 위해 설정이나 선택 절차를 추정해서 쓰지 않는다.

### 3단계 — 남는 핵심 쟁점에 한해 추가 실험 선택

| 후보 | 선택할 조건 | 우선순위 판단 |
|---|---|---|
| POMCP-Q gamma / simulation budget 또는 time-matched 평가 | 가장 강한 baseline의 설정 공정성이 기존 자료만으로 설명되지 않을 때 | Matching 단위를 정의하고 baseline 격차의 해석을 보강 |
| Belief-entropy 기반 planning baseline | 문헌 확인 후 질의 분리의 장점을 직접 비교할 필요가 있을 때 | 리뷰 3의 신규 제안. 같은 belief·query 모델·reward·budget으로 구성할 수 있는지 먼저 검토 |
| 동일한 planner에서 timing·selection 통제 | 기존 ablation을 검토해도 실제 통제가 부족할 때 | 현재 T1/S1 비교를 먼저 활용하고 남는 공백만 보완 |
| 별도 configuration/seed 평가 | 설정 선택과 최종 평가가 분리되지 않았고 일반화 주장을 유지할 때 | 선택 편향 및 분포 밖 확인의 목적을 명시 |
| 응답 오류 주입 | 실제 심사에서 기존 VLM·사람 평가로 답하지 못하는 오류 민감도 요구가 제기될 때 | 현재 제출 전 선제 대응에서 제외 |
| Soft update / full-history belief | 향후 연구 범위 확장 또는 실제 심사 대응으로 별도 결정할 때 | 현재 제출 전 선제 대응에서 제외. 새 방법과 재평가를 요구하는 작업 |
| 새로운 workload 측정·참가자 추가 | 인지 부담 감소나 사용자 일반화를 핵심 주장으로 삼을 때 | 현재 논문의 정성적 인터뷰 보완과는 다른 연구 범위 |

리뷰 1의 ‘동일 planner baseline 필수’, 리뷰 2의 ‘soft update 추가’, 리뷰 3의 ‘rho-POMCP 또는 time-matched 비교’를 자동적인 완료 조건으로 삼지 않는다. 수정 후에도 유지하려는 주장에 어떤 근거가 부족한지를 기준으로 선택한다.

## 7. 분량 목표에 맞춘 반영 방식

현재 목표는 본문을 줄이고 부록을 5페이지 이내로 유지하는 것이다. 리뷰 대응을 이유로 삭제한 부록 전체를 복원할 필요는 없다.

| 위치 | 반영할 핵심 | 공간 확보 방법 |
|---|---|---|
| Abstract | 중복 제거, 평가 범위 명확화 | 평가 문장 하나 삭제 |
| Introduction | 한 단계 belief와 질의 정책의 역할을 정확하게 설명 | 기존 belief 설명 교체 |
| Related Work | 검증된 belief-dependent planning 및 predicate verification 연구와의 차이 | 나열식 문헌 요약 대신 when/what/belief 기준으로 통합 |
| Method | POMCP particles와 verification belief, MAP 확정, query 분리 및 frontier 구성 | 기존 설명을 합쳐 짧게 교체 |
| 실험 설정 | 모델 출처·reward·설정 선택의 근거 | 반복 플랫폼·지표 설명 축약 |
| Ablation | 통제된 비교의 큰 틀과 조건부 결론 | 표에서 바로 읽히는 수치 나열을 줄임 |
| Discussion | 응답 오류, MAP 근사, 사람 평가의 범위 | 중복 결과 요약 대신 한계와 해석 배치 |
| Appendix | 파라미터와 프롬프트 및 필요한 절차 유지 | 알고리즘·확률표·본문 결과 중복은 복원하지 않음 |
| 코드·설정 | 상세 모델 값, reward, 전체 prompt, 추가 분석 자료 | 논문에서 위치를 명확하게 연결 |

**먼저 고칠 것은 논문의 결론이 아니라 결론의 근거를 연결하는 방식이다.** 높은 성공률이라는 관측 결과는 유지하되, timing의 역할은 통제된 ablation으로 설명하고, 사람 인터뷰와 시스템 간 차이는 해당 평가가 허용하는 범위에서 해석한다. 그다음 기존 기록으로 남는 질문에 답하고, 설명만으로 해결되지 않는 핵심 문제에 한해 추가 실험을 결정한다.


## 8. 세 번째 리뷰 반영에 따른 우선순위 변화

리뷰 3은 기존 분석의 핵심 방향을 뒤집지 않는다. Frontier/MAP와 응답 오류에 대한 설명이 필요하다는 판단을 강화하면서, **질의를 탐색에서 분리한 설계의 위치와 가장 가까운 정보 수집 planning 계열과의 비교**를 추가한다.

1. **즉시 원고 정리** — 기존 편집 오류와 belief 서술을 정리하고 query 분리의 설계 범위를 명시한다.
2. **기존 근거 확인** — T/O·reward 출처, frontier 구성, gamma 선택, 실제 계산 budget을 확인한다.
3. **관련 연구 검증** — 리뷰 3이 제시한 후보의 원 논문을 확인해 이미 다룬 연구와 실제로 빠진 비교를 구분한다.
4. **추가 요구는 별도 판단** — 새로운 baseline이나 budget 비교를 제출 전 기본 계획으로 삼지 않는다. 현재 주장에 실제 근거 부족이 확인되거나 실제 심사에서 구체적으로 요구될 때 대응 범위를 결정한다.

이번 갱신은 분석 문서에만 반영했으며, 제안된 문헌을 검증하거나 baseline을 새로 구현한 것은 아니다.


## 9. 이번 저자 논의에서 확정한 처리 방향

- 정당하지 않거나 검증되지 않은 리뷰 지적을 선제적으로 방어하기 위해 본문을 늘리지 않는다.
- Reward 기반 gamma는 baseline과 맞춘 설정으로 설명하며, 그 차이만으로 실험을 불공정하다고 규정하지 않는다.
- MAP 선택은 외부 응답에 대한 신뢰, 후속 상태 후보의 누적 제한, 질의로 충분한 confidence를 확보한 뒤 계획을 이어가려는 설계와 연결해 설명한다. 질문 후보 소진 시 종료되는 예외도 실제 알고리즘대로 구분한다.
- 잔여 가설이 ‘의미 없다’고 단정하지 않고, confidence 기준 아래에서 다음 계획으로 전달하지 않는 선택으로 설명한다.
- Hard filtering의 취약성은 인정하되, 실제 응답을 사용하는 VLM·사람 평가와 실패 분석이 이미 있다는 점을 함께 본다.
- 사람 평가에서 관측한 90%·100% 성공과 응답 오류 실패 한 건은 현재 조건에서의 결과로 보고한다. 이를 응답 오류 전반에 대한 보장으로 확대하지 않는다.
- Soft update, full-history belief, 오류 주입과 새 baseline은 현재 제출 전 작업 목록에 추가하지 않는다.
- 먼저 필요한 설명과 편집 오류만 정리해 제출하고, 추가 요구는 실제 심사의 내용에 따라 판단한다.
