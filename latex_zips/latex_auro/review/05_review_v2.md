**제가 Autonomous Robots의 리뷰어라면, 현재 원고에는 Reject를 권고하겠습니다.** 주제와 실제 로봇 구현은 AR에 잘 맞습니다. 그러나 핵심 성능 차이를 질문 정책의 기여로 해석하기에는 비교 조건에 문제가 있고, belief 갱신 방식도 논문의 문제 설정을 충분히 뒷받침하지 못합니다. 이 부분은 결과 해석을 바꿀 수 있어, 현재로서는 문장 수정 중심의 revision보다 핵심 검증을 보완한 재투고가 적절하다고 봅니다.

검토 대상은 본문과 부록을 포함한 21쪽 원고입니다. 코드·실행 로그·별도 보충자료는 확인하지 않았으므로, 아래에서는 **원고에 명시된 문제와 구현 확인이 필요한 문제를 구분**하겠습니다. BRL_achitecture(1).pdf

먼저 AR의 기준을 어떻게 적용했는지 말씀드리겠습니다. 공식 scope는 로봇 자율성의 계산적 측면을 다루며, computational architectures, human–robot interaction, planning, autonomous robot systems를 명시적으로 포함합니다. 특히 **실제 환경에서 물리 로봇의 성능 데이터를 제시하는 논문을 우대**한다고 밝힙니다. 따라서 이 논문은 저널 적합성과 실험 구현 측면에서 유리합니다. 다만 공개된 세부 채점표가 있는 것은 아니므로, 아래의 기여·타당성 판단은 그 scope에 근거한 제 심사 판단입니다. [Springer Nature Link](https://link.springer.com/journal/10514/aims-and-scope?utm_source=chatgpt.com)

제 평가는 다음과 같습니다.

| 평가 항목 | 판단 | 주된 이유 |
|---|---|---|
| AR 주제 적합성 | 높음 | 불확실한 상태에서 로봇이 스스로 도움을 요청하는 문제 |
| 실제 로봇 검증 | 상당한 강점 | 2개 도메인, VLM 및 인간 피드백 실험 |
| 학술적 독창성 | 현재 설명으로는 제한적 | entropy 기반 질문 선택을 넘어서는 기여가 충분히 분리되지 않음 |
| 방법의 기술적 타당성 | 중요한 확인 필요 | 단일 MAP 상태에서 다음 belief를 구성하는 근사와 그 영향 |
| 비교 실험의 설득력 | 부족 | 종료 예산 차이, 계획기·실행 가능성 처리 차이 |
| 재현 가능성 | 부족 | 확률 모델·보상·calibration의 핵심 정보 부족 |
| 종합 권고 | **Reject** | 주요 결론을 확정하려면 비교 재실험과 방법 검증이 필요 |

이 논문에서 긍정적으로 평가할 부분도 분명합니다. **‘사람에게 다음 행동을 정하게 하기보다, 상태 사실을 확인받고 계획은 로봇이 수행한다’는 설계는 로봇 자율성 관점에서 의미가 있습니다.** 사용자가 행동의 전제조건까지 판단해야 하는 부담을 줄일 수 있고, 그 차이를 실제 시스템으로 구현했습니다.

실험도 단순한 성공 시연 수준은 아닙니다. 시뮬레이션은 조건별 200회이고, 실제 로봇에서는 VLM 실험 총 160회와 인간 실험 총 40회를 보고합니다. 특히 Table 3의 **S1과 Ours 비교**는 비교적 설득력이 있습니다. confidence 기반 timing을 고정했을 때, Sort에서는 성공률 100%를 유지하면서 질문 수가 15.21에서 7.83으로 줄고, Harvest에서도 성공률이 거의 같은 상태에서 12.68에서 9.16으로 줄었습니다. 이는 현재 원고에서 가장 직접적으로 뒷받침되는 결과입니다.

그럼에도 Reject를 권고하는 이유는 다음과 같습니다.

1. **가장 명확한 문제는 POMCP-Q에 적용한 종료 예산이 다르다는 것입니다.**

   Appendix A.1, p.17에서 다른 방법에는 **물리 행동 50회**를 허용하지만, POMCP-Q에는 **질문과 물리 행동을 합쳐 50회**를 허용한다고 명시합니다.

   예를 들어 질문 30회와 물리 행동 21회가 필요한 실행은, 이 제한만 놓고 보면 Ours에서는 허용되지만 POMCP-Q에서는 완료할 수 없습니다. 질문을 planning action으로 표현한 방법에만 질문이 추가 종료 비용으로 작용합니다.

   이것이 보고된 성공률 차이 전체를 설명한다고 단정할 수는 없습니다. 그러나 **100% 대 87%, 98% 대 57.5%라는 핵심 비교를 그대로 질문 전략의 우수성으로 해석할 수 없게 만드는 조건**입니다. 동일한 물리 행동 한도와 공통 시간·질문 예산을 적용하고, 기존 POMCP-Q 실패 중 몇 건이 이 제한 때문인지 제시해야 합니다.

   또한 POMCP-Q의 explicit query cost는 0입니다. 할인으로 인한 간접 비용은 있지만, 질문 수를 직접 줄이도록 설정된 목적함수는 아닙니다. 따라서 질문 수가 많다는 결과를 근거로 reward-based querying 자체가 비효율적이라고 일반화하기는 어렵습니다. 질문 비용과 탐색 예산에 따른 성능 곡선이 필요합니다.

2. **KnowNo와의 비교는 전체 시스템의 차이는 보여주지만, 제안한 질문 정책의 효과를 충분히 분리하지 못합니다.**

   Ours는 명시적인 symbolic action model과 적용 가능한 행동을 제한하는 POMCP를 사용합니다. KnowNo와 IntroPlan은 LLM으로 행동 후보를 생성하고 평가합니다. 실제 실패 분석에서도 KnowNo의 상당수 실패는 물체를 집기 전에 놓으려 하거나, 필요한 detection을 거치지 않고 pick을 선택하는 등 전제조건과 관련됩니다.

   따라서 관측된 차이에는 적어도 **질문 시점, 질문 내용, 행동 생성, 전제조건 처리**가 함께 들어 있습니다. 시스템 전체를 비교하는 실험으로는 유효하지만, 질문 방식이 성공률 차이를 만들었다는 설명에는 추가 통제가 필요합니다.

   특히 KnowNo 원논문은 보장의 전제로 환경 정보가 입력에 충분히 grounding되고 제안 행동이 성공적으로 실행될 수 있음을 명시합니다. 현재 원고는 perception uncertainty와 실행 전제조건의 불확실성을 중심으로 평가하므로, 이러한 적용 조건 차이를 분명하게 설명해야 합니다. [proceedings.mlr.press](https://proceedings.mlr.press/v229/ren23a/ren23a.pdf?utm_source=chatgpt.com)

   저는 KnowNo 비교를 없애라고 하지는 않겠습니다. 대신 **동일한 행동 실행 기반에서 질문 정책을 바꾼 비교**, 또는 KnowNo에 동일한 전제조건 검사 기능을 제공한 비교를 요구하겠습니다. Appendix A.2에는 calibration threshold가 있지만, calibration 데이터 규모·구성·분리 방식과 실제 test coverage가 없어 구현의 적절성도 판단하기 어렵습니다. 95% coverage 설정과 낮은 task success가 곧 모순인 것은 아니지만, 그 간극의 원인은 밝혀야 합니다.

3. **현재의 belief 갱신은 ‘이전 불확실성을 계속 추적하는 방식’과 중요한 차이가 있습니다.**

   p.4의 Eq. (2)는 다음 상태의 가중치를 다음과 같이 계산합니다.

   \[
   w_k\propto T(s'_k\mid s_t^K,a_t)\,O(o_{t+1}\mid s'_k,a_t).
   \]

   여기서 출발점은 이전 belief 전체가 아니라 단일 knowledge state \(s_t^K\)입니다. Algorithm 1에서는 질문 후 MAP 상태를 선택하고, 다음 UPDATE가 그 상태를 사용합니다. SEARCH에는 belief를 전달하지만, **다음 belief를 구성하는 단계에서는 직전 MAP 상태에 조건화**합니다.

   이 근사는 효율을 위한 설계가 될 수 있습니다. 다만 어떤 불확실성을 버리고, 그로 인한 오류를 어떻게 처리하는지가 중요합니다.

   예를 들어 물체가 plastic일 확률을 0.99, can일 확률을 0.01로 추정하면, Eq. (3)의 confidence는 약 0.919여서 기본값 \(\tau=0.8\)에서는 질문하지 않습니다. 이후 plastic을 MAP 상태로 선택하고, 다음 pick 행동이 물체 종류를 바꾸지 않는다면, 기술된 방식에서는 다음 frontier에도 plastic 상태만 포함될 수 있습니다. 실제 물체가 can이었다면 **올바른 가설이 질문 후보를 만드는 belief에서 사라지는 것**입니다.

   이는 외부 답변 오류만의 문제가 아닙니다. 논문이 문제 삼는 **확신을 가진 잘못된 인식**이 제안 방법에서도 해결되지 않을 수 있다는 뜻입니다.

   따라서 저는 이를 바로 구현 오류라고 단정하기보다, **현재 수식대로 구현했는지, 별도의 가설 복원 과정이 있는지, 근사가 허용되는 조건이 무엇인지**를 요구하겠습니다. 이 부분이 불분명하면 partial observability에 대한 방법론적 주장을 평가하기 어렵습니다.

4. **독창성은 ‘entropy를 사용한다’보다 구체적인 수준에서 입증되어야 합니다.**

   현재 주요 구성은 normalized entropy threshold, expected entropy reduction에 따른 질문 선택, 응답에 따른 hypothesis filtering, POMCP입니다. 정보이론을 이용해 로봇의 질문을 선택하는 원리는 이미 오래된 연구 흐름입니다. 예를 들어 Deits 등의 연구는 yes/no 질문의 entropy와 질문 후 예상 entropy를 이용한 선택을 다룹니다. 문제 설정은 다르지만, 이 논문의 질문 선택 원리와 비교해야 할 선행연구입니다. [cs.brown.edu](https://cs.brown.edu/people/stellex/publications/deits13.pdf?utm_source=chatgpt.com)

   특히 현재처럼 답이 정확하고 질문이 상태의 Boolean fact를 확인한다면,

   \[
   H(S)-\mathbb{E}[H(S\mid q)]=H(q).
   \]

   따라서 Eq. (4)는 후보 중 참일 확률이 0.5에 가장 가까운 fact를 선택하는 것과 같습니다. 유효하고 간결한 기준이지만, 그 식 자체에 큰 독창성을 부여하기는 어렵습니다.

   **AR에서 기여가 될 가능성이 높은 부분은 symbolic frontier와 fact-verification을 실제 로봇의 계획·실행 과정에 연결한 설계입니다.** 그러려면 frontier가 어떤 계산적 이점이나 오류 감소를 만드는지, 기존 belief 기반 질의 방법에 비해 무엇이 개선되는지를 보여줘야 합니다. 현재 실험은 그 부분을 직접 분리하지 않습니다.

5. **핵심 확률 모델의 명세와 검증이 부족합니다.**

   이 방법의 질문 여부는 \(T\), \(O\), frontier 구성에 크게 좌우됩니다. 그런데 본문과 부록만으로는 다음을 재현하기 어렵습니다.

   - 도메인별 transition·observation probability의 구체적인 정의와 추정 방법
   - noisy observation과 action failure의 발생 조건
   - frontier sampling 방식, 중복 처리, 누락된 상태의 처리
   - task reward를 포함한 전체 보상 함수
   - 초기 장면 구성의 종류와 조건별 난이도 분포

   특히 **명시적 확률 모델을 제공받은 방법과 LLM 기반 방법의 차이**를 평가하려면, 그 모델을 만드는 데 필요한 정보와 작업량도 드러나야 합니다.

   Appendix A.3의 ablation에도 확인할 부분이 있습니다. T3·S2의 discount factor가 다른 조건과 다릅니다. 이것이 질문 평가에만 적용되는지, 실제 행동 선택에도 적용되는지 명확하지 않습니다. 후자라면 질문 정책 외에 행동 계획도 달라집니다. T2는 질문 시작뿐 아니라 계속 질문할지 결정하는 규칙도 다르므로, 결과를 해석할 때 이를 함께 설명해야 합니다.

6. **실제 로봇 결과는 강점이지만, 효율성과 일반성에 대한 증거에는 한계가 있습니다.**

   Table 2의 비용 지표는 성공한 시행만 사용합니다. 인간 Sort에서는 KnowNo의 성공이 2회, Ours는 9회이므로, 두 방법의 평균 시간은 서로 다른 작은 시행 집합의 평균입니다. 성공한 실행의 비용을 보고하는 것은 가능하지만, 전체 운용 효율을 판단하려면 실패까지 포함한 비용이나 공통 예산에서의 성공률도 필요합니다.

   또 **인간 참가자 5명 자체를 Reject 사유로 삼지는 않겠습니다.** 보조적인 사용성 관찰과 인터뷰로는 가치가 있습니다. 다만 반복 시행을 독립적인 참가자 증거처럼 해석해서는 안 되고, 인지 부담이나 선호에 관한 일반화는 제한해야 합니다.

   피드백 오류도 p.14에서 솔직하게 인정합니다. 그러나 실제 VLM 실험에서 Ours의 실패가 모두 잘못된 답변과 관련된다면, 응답 정확도에 따라 성공률과 질문 수가 어떻게 달라지는지 분석할 가치가 큽니다. AR의 실제 자율 시스템 관점에서는 **언제 잘 작동하고 언제 취약해지는지**가 중요한 결과입니다.
