# 11 TODO — E3 Active Search audit

## Active Search action evaluation

`scripts/baseline/attr_pomdp/scripts/belief.py::_predict_and_reward` currently
skips a belief particle when the candidate action does not satisfy that
particle's preconditions. The skipped probability mass receives neither a
failed transition nor a failure penalty. This can overestimate risky task
actions and underestimate the value of asking a question.

Required change:

- Keep precondition checking.
- Do not discard non-applicable particles.
- Model them as a failed/no-op transition with the domain-consistent failure
  reward, and include their probability mass in the expected value.
- Add a unit test with a two-particle belief where an action is applicable in
  only one particle. The expected value must include both particles.

## E3 comparison fairness

- Active Search currently counts both query and task actions against
  `MAX_STEP`; Ours counts queries inside a task step. Define and enforce one
  common task-step budget, while logging query count separately.
- E3 forces Active Search planning depth to 2 while Ours uses a longer POMCP
  horizon. Justify this approximation or select the horizon through validation.
- Active Search planning contains deterministic detect shortcuts while runtime
  execution uses the shared stochastic environment. Remove or document this
  model mismatch.
- Keep the method name `grounded-fact Adapted Attr-POMDP`; do not describe it as
  a full reproduction of the original vision-based Attr-POMDP.
