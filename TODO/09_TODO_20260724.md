## 0. 이번 문서의 목적

Related-work qualitative table에서는 제안 시스템을 다음 다섯 축으로 설명한다.

1. Interpretable Knowledge
2. Symbolic Action Model
3. Uncertainty Planning
4. Human Feedback
5. System-Initiated Query

이 다섯 요소를 각각 최초로 제안했다고 주장하지 않는다. 개별 요소는 기존

각 축이 실제로 어떤 역할을 하는지 분리해서 검증한다.

## 1. 현재 시스템의 정확한 질의 구조

제안 방법에서 질의는 POMDP action space에 포함되지 않는다.

```text
A = A_task
```

기본 실행 흐름은 다음과 같다.

```text
task action planning
→ action execution
→ transition model에 따른 결과 예측
→ observation 수신
→ predicted transition과 observation의 consistency 검사
→ 일치하면 일반 belief update
→ 충돌하면 관련 grounded fact에 대해 feedback 요청
→ feedback을 belief와 knowledge에 반영
→ replanning
```

따라서 질의는 미래 information value를 얻기 위해 planner가 선택하는 행동이
아니다. Task action 실행 후 transition prediction과 observation이 양립하지 않을
때 호출되는 **corrective feedback mechanism**이다.

### 1.1 08_TODO와 정합성 수정 필요

`08_TODO_20260723.md`에는 현재 방법이 normalized belief entropy로 질문 필요성을
판단한다고 작성되어 있다.

```text
08_TODO:
  entropy/confidence threshold
  → query

현재 대화에서 확정한 framing:
  transition prediction–observation conflict
  → query
```

논문, 코드와 실험 설계에서 둘 중 무엇이 실제 구현인지 확인하여 용어를 통일해야
한다. 둘을 함께 사용한다면 역할을 분리해 명시해야 한다.

```text
가능한 결합:
  conflict detection = query opportunity 생성
  entropy/confidence = 실제 외부 질문 여부 판단
```

현재 contribution을 conflict-triggered query로 주장하려면 E1의 threshold
설명과 related-work 문장도 함께 수정해야 한다.

## 2. 세 Main Baseline의 비교축

비교할 세 방법은 모두 system-initiative feedback을 다루지만, 질문 trigger가
다르다.

```text
KnowNo:
  현재 prediction이 통계적으로 모호한가?

Adapted Attr-POMDP:
  query action의 future expected return이 task action보다 높은가?

Ours:
  predicted transition과 execution observation이 충돌하는가?
```

### 2.1 전체 비교

| 비교 기준 | KnowNo 계열 | Adapted Attr-POMDP | Ours |
|---|---|---|---|
| 핵심 원리 | Conformal prediction | Query를 POMDP action으로 포함 | Transition–observation conflict |
| 질문의 위치 | Action prediction 검증 단계 | Planner action space 내부 | Execution/belief-update 단계 |
| 질문 시점 | Prediction set이 하나로 좁혀지지 않을 때 | Query의 expected return이 task action보다 클 때 | Prediction과 observation이 양립하지 않을 때 |
| 질문 대상 | Prediction set의 action 후보 | Belief에서 불확실한 attribute fact | 충돌과 관련된 grounded fact |
| 불확실성 기준 | Calibration score와 threshold | Bayesian belief, reward와 query cost | Model–observation consistency |
| Task model 사용 | 상대적으로 약함 | Transition/observation/reward 사용 | Transition과 observation의 구조적 관계 사용 |
| 질문 비용 | Set-size/coverage trade-off | Query action reward | Feedback cost |
| 주요 장점 | 통계적 coverage | 질문의 장기적 가치 계산 | 실행에 문제가 된 불확실성만 교정 |
| 주요 부담 | Calibration distribution 의존 | Query action과 observation branch 증가 | 충돌 전에 선제적으로 묻지 않음 |

### 2.2 KnowNo와 비교해 보고 싶은 것

```text
Conformal ambiguity만으로 질문하는 것보다
task transition의 실제 충돌을 이용하는 것이 효과적인가?
```

KnowNo는 calibration distribution과 exchangeability 가정 아래에서 prediction
coverage를 제공한다. 하지만 prediction set이 큰 원인이 현재 task execution에
중요한지는 직접 구분하지 않는다.

Ours는 실행한 action의 predicted effect와 실제 observation 사이의 충돌을
사용한다. 따라서 질문이 현재 task execution 및 belief correction과 직접
연결된다.

검증 지표:

- Task success rate
- Average query count
- Query precision/relevance
- Cumulative reward
- Distribution shift에서의 성능
- Invalid 또는 failed action 반복 횟수

### 2.3 Adapted Attr-POMDP와 비교해 보고 싶은 것

```text
질문을 action으로 넣고 선제적으로 계획하는 것보다,
실행 충돌이 발생했을 때 corrective feedback을 요청하는 것이
일반 task planning에서 효율적인가?
```

공정한 비교를 위해 다음 요소를 동일하게 둔다.

```text
동일 domain transition
동일 task action
동일 task reward
동일 initial belief
동일 Oracle
동일 query 가능한 fact
```

차이는 query architecture에만 둔다.

```text
Adapted Attr-POMDP:
  A = A_task ∪ A_query
  task action과 query action의 expected return 비교

Ours:
  A = A_task
  execution conflict가 발생하면 planning 외부에서 query
```

검증 지표:

- Task success rate
- Average query count
- Planning/search time
- Action/query branching에 따른 계산량
- Cumulative reward
- 질문 없이 해결할 수 있었던 uncertainty에 대한 불필요한 query 비율

### 2.4 Related-work 표와 experimental baseline의 구분

Related-work 표의 `POMDP-based planning` 또는 원 Attr-POMDP는 explicit symbolic
task action model이 없다고 분류할 수 있다. 그러나 실험에서 사용하는
`Adapted Attr-POMDP`는 공정성을 위해 우리의 domain transition system을 공유한다.

```text
Related-work table:
  원 논문의 특성을 분류

Experimental baseline:
  Attr-POMDP의 action–query planning 원리를
  현재 domain transition system에 적용
```

논문에서 이 둘을 구분하지 않으면 다음 반론을 받을 수 있다.

```text
“표에서는 symbolic action model이 없다고 했는데,
실험 baseline에는 왜 같은 symbolic transition을 사용하는가?”
```

따라서 baseline은 반드시 `Adapted Attr-POMDP`라고 표기하고 adaptation 내용을
명시한다.

## 4. Symbolic Action Model이 필요한 이유

Symbolic action model의 장점은 단지 symbol을 사용해서 사람이 읽을 수 있다는
것이 아니다. 우리 시스템에서는 충돌을 정의하고 질문 대상을 찾는 계산적
기반이다.

예:

```text
Action:
  pick(robot, tomato1)

Preconditions:
  ripe(tomato1)
  at(tomato1, stem1)
  handempty(robot)

Effects:
  holding(robot, tomato1)
  not handempty(robot)

Expected observation:
  holding(robot, tomato1)
```

실행 후 `holding(robot, tomato1)`이 관측되지 않으면 action model을 통해 다음을
추적할 수 있다.

1. 어떤 action의 예상 결과가 달랐는가?
2. 어떤 precondition에 의존했던 action인가?
3. 어떤 effect가 발생하지 않았는가?
4. 어떤 grounded fact를 확인해야 belief를 교정할 수 있는가?

```text
action
→ required facts
→ predicted effects
→ expected observations
→ detected conflict
→ candidate causes
→ targeted query
```

Action model이 없다면 `pick`이 실패했다는 사실은 알 수 있어도 다음 중 무엇이
원인인지 구조적으로 제한하기 어렵다.

```text
ripe(tomato1)?
at(tomato1, stem1)?
handempty(robot)?
holding(robot, tomato1)?
```

### 4.1 Symbolic Action Model의 세 역할

#### A. 실행 가능한 action 제한

명시적인 precondition으로 현재 belief에서 실행 가능한 action을 제한한다.

#### B. Observation 충돌에 의미 부여

단순히 prediction confidence가 낮다는 것이 아니라, 어떤 precondition/effect와
observation이 충돌했는지 표현한다.

#### C. Query space 제한

모든 uncertain fact를 대상으로 하지 않고, 현재 action의 precondition/effect 및
관측 충돌과 관련된 fact를 질문 후보로 만든다.

따라서 symbolic action model의 핵심 장점은 다음과 같다.

> Symbolic action model connects query timing and content to explicit task
> semantics.

한국어:

> Symbolic action model은 질문 시점과 질문 내용을 명시적인 task semantics에
> 연결한다.

### 4.2 한계도 명시

- Domain action schema를 사람이 정의해야 한다.
- Action model이 틀리면 정상 observation을 충돌로 판단할 수 있다.
- Model에 표현되지 않은 failure cause는 질문 후보가 되지 않을 수 있다.
- Learned/black-box dynamics보다 구축 비용이 높을 수 있다.

따라서 symbolic model이 언제나 우월하다고 주장하지 않는다. 본 연구에서는
task-level precondition/effect가 정의 가능한 domain에서 targeted feedback의
근거를 제공한다는 점을 주장한다.

### 5.1 최소 Main Experiment

### 5.2 Symbolic Action Model 검증용 핵심 ablation

전체 planner에서 symbolic transition을 제거하는 비교는 공정하게 정의하기 어렵다.
대신 **query selection에서 action model의 guidance만 제거**한다.

#### Full Ours

```text
conflicting action
→ relevant precondition/effect
→ related grounded fact query
```

#### Ours without action-model-guided query

```text
same conflict timing
→ 모든 uncertain fact를 candidate로 사용
→ 가장 uncertain한 fact 또는 random fact query
```

통제 조건:

```text
동일 conflict trigger
동일 belief
동일 task planner
동일 Oracle
동일 query budget
```

비교 지표:

- Task success rate
- Average query count
- Query relevance
- Conflict resolution rate
- 동일 failure action 반복 횟수
- Recovery까지 필요한 step 수

Full Ours가 더 적은 질문으로 더 높은 conflict resolution과 task success를
달성하면 다음과 같이 해석한다.

> Symbolic action model is not merely a representation choice; it constrains
> the query space to task-relevant facts associated with the conflicting
> action.

## 7. Interpretable Knowledge 검증

Interpretability는 task success만으로 증명하기 어렵다. 다음과 같은 execution
trace를 사례로 제시한다.

```text
Executed action:
  pick(robot, tomato1)

Predicted effect:
  holding(robot, tomato1)

Observed:
  handempty(robot)

Conflict:
  expected holding but observed handempty

Candidate causes:
  ripe(tomato1)
  at(tomato1, stem1)

Selected query:
  Is tomato1 ripe?

Feedback:
  No

Belief correction:
  unripe(tomato1)
```

가능한 평가 지표:

- Query가 실제 conflict cause와 관련 있는 비율
- Feedback 후 해당 conflict가 해소되는 비율
- Generated explanation의 fact-level 정확도
- 사용자가 query 이유를 이해한 비율
- Explanation usefulness에 대한 사용자 평가

논문 분량이 제한되면 대표 사례 2–3개와 query relevance/conflict-resolution
metric을 사용한다.

## 8. “왜 Ours가 좋은가?”에 대한 안전한 주장

실험 전에 모든 상황에서 우월하다고 주장하지 않는다. 다음 가설을 검증한다.

### 8.1 Query action으로 planning space를 확장하지 않음

```text
Adapted Attr-POMDP:
  |A_task| + |A_query|

Ours:
  |A_task|
```

Ours는 conflict가 발생했을 때만 query candidate를 생성한다. 질문 가능한 fact가
많은 domain에서 planning time에 유리할 가능성이 있다.

### 8.2 Task execution에 문제가 된 uncertainty에 집중

```text
uncertain but transition-consistent:
  task execution 계속

uncertain and transition-inconsistent:
  feedback 요청
```

모든 uncertainty를 제거하지 않고 실제 execution과 belief update를 방해하는
불확실성에 집중한다.

### 8.3 Calibration dataset 의존성 감소

KnowNo의 coverage는 calibration/test exchangeability에 의존한다. Ours는 현재
episode의 transition–observation relation에서 발생한 충돌을 직접 사용한다.

### 8.4 기존 task planner 유지

Query를 planner action space와 transition tree에 추가하지 않는다. 기존 task
planner를 유지하고 execution/belief-update layer에 conflict detection과 feedback
update를 결합한다.

### 8.5 예상 한계

- Irreversible 또는 safety-critical action에서는 충돌 후 질문이 늦을 수 있다.
- 잘못된 belief가 observation과 우연히 일치하면 질문하지 않을 수 있다.
- Transition/observation model misspecification에 영향을 받는다.
- 선제적 정보 획득이 중요한 상황에서는 Attr-POMDP가 더 유리할 수 있다.

안전한 주장:

> In long-horizon task planning domains with many queryable facts, most
> uncertainty does not necessarily require external verification. We
> hypothesize that conflict-triggered feedback can retain task performance
> while reducing unnecessary queries and avoiding the expansion of the
> planner's action space.

## 9. Contribution 및 Novelty 문장

### 9.1 피해야 할 주장

```text
We are the first to introduce:
  interpretable knowledge,
  symbolic action models,
  uncertainty planning,
  human feedback,
  and system-initiated queries.
```

각 요소에는 이미 선행연구가 있으므로 다섯 개를 독립적인 최초 기여로 주장하면
안 된다.

### 9.2 권장 영문

```text
Unlike prior approaches that treat uncertainty planning, human feedback,
and system-initiated querying separately, our framework integrates them
through an explicit symbolic action model. The model connects action
preconditions and effects to predicted observations, enabling the system
to detect execution-time inconsistencies, identify task-relevant uncertain
facts, and initiate targeted human feedback without introducing query
actions into the planner's action space.
```

### 9.3 권장 한국어

```text
본 연구의 기여는 symbolic knowledge, uncertainty planning과 human feedback
각각을 새로 제안하는 것이 아니라, 명시적인 symbolic action model을 중심으로
이 요소들을 연결한 것이다. Action의 precondition과 effect로부터 예상
observation을 구성하고, 실행 observation과의 충돌을 감지하며, 충돌 원인과
관련된 grounded fact에 대해서만 시스템이 feedback을 요청한다. 이때 질의는
planner의 action space에 포함되지 않는다.
```

## 10. 교수님 질문에 대한 짧은 답변

### Q. Related-work의 다섯 축을 실험에서 어떻게 검증합니까?

```text
다섯 축을 baseline 하나로 모두 검증하지 않습니다. KnowNo와 Adapted
Attr-POMDP 비교는 system-initiated query의 기준과 architecture를 검증합니다.
No-feedback 및 MAP ablation은 human feedback과 uncertainty planning의 효과를
검증합니다. Symbolic action model은 동일한 conflict trigger를 유지하면서
질문 대상을 action의 precondition/effect로 제한하는 full model과, 전체 uncertain
fact에서 질문하는 ablation을 비교해 검증합니다. Interpretable knowledge는
fact-level execution trace와 query relevance 또는 사용자 평가로 확인합니다.
```

### Q. Symbolic action model은 왜 좋은가요?

```text
단순히 symbol이라서 좋은 것이 아닙니다. Action의 precondition과 effect가
명시되어 있기 때문에 예상 transition과 observation의 충돌을 의미적으로
해석하고, 그 충돌과 관련된 task fact로 query space를 제한할 수 있습니다.
따라서 symbolic action model은 본 시스템에서 conflict detection과 targeted
feedback을 연결하는 계산적 기반입니다.
```
