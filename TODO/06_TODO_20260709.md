# 2026-07-09 논문 실험 포장 전략

## 1. PPT 기준 논문 주장

`14_AIRLAB_BRL_박창민.pptx` 기준으로 논문은 **planning 중심 system 논문**으로 잡는다.

핵심 문제 정의:

```text
현실 환경에서 동작하는 로봇은 partial observability 때문에
현재 상태를 완전히 알 수 없다.

작은 상태 오판이 누적되면 잘못된 행동 선택으로 이어지고,
결국 전체 task failure가 발생할 수 있다.

사람은 로봇이 직접 관측하기 어려운 정보를 제공할 수 있지만,
지속적인 질문은 사용자 부담을 증가시킨다.

따라서 로봇은 언제 질문할지, 무엇을 질문할지,
그리고 어떤 형식으로 질문할지를 결정해야 한다.
```

논문 중심 문장:

```text
부분 관측 환경에서 로봇은 planning에 필요한 정보를 스스로 식별하고,
query를 통해 task-relevant uncertainty를 줄이며,
그 응답을 belief update와 replanning에 반영한다.
```

## 2. 세 가지 Contribution: When / What / How

우리 논문의 contribution은 `When / What / How`로 정리한다.

### 2.1 When: 질의 시점

```text
우리는 부분 관측 환경에서 현재 행동 선택의 불확실성을 정량화하여,
로봇이 사람의 도움이 필요한 시점을 스스로 판단하는
질의 시점 결정 프레임워크를 제안한다.
```

PPT 표현:

```text
질의 시점을 정량화
필요할 때만 질문해서 사용자의 부담 감소
```

실험으로 보여줄 것:

```text
Ours가 All보다 적은 질문으로 비슷한 성공률을 유지하는가?
Ours가 No보다 높은 성공률을 보이는가?
Ours가 Random보다 안정적인가?
```

### 2.2 What: 질의 내용

```text
우리는 로봇이 자신의 행동 선택에 필요한 상태 정보를 식별하고,
이를 질의 대상으로 선택하는 방법을 제안한다.
```

PPT 표현:

```text
필요한 질의 내용을 로봇 스스로 결정
잘못된 상태 인지를 구조적으로 잡기
```

실험으로 보여줄 것:

```text
로봇이 task와 무관한 질문을 많이 하지 않는가?
선택된 predicate가 action selection / failure prevention에 실제로 기여하는가?
Active Search처럼 query/search 후보를 넓히는 방식보다 효율적인가?
```

### 2.3 How: 질의 형식

중요: 여기서 `How`는 단순히 "응답을 belief update에 어떻게 넣는가"가 아니다.
PPT 기준 `How`는 **질문을 어떤 형식으로 하느냐**다.

정확한 주장:

```text
우리는 불확실성을 상태 단위로 질의하여,
사용자의 피드백이 특정 상태 변수에 대응되도록 하는 질의 형식이
더 효과적임을 보인다.
```

PPT 표현:

```text
상태 단위 질의가 planning에 더 효과적
상태 기반 질의가 사용자의 부담 감소
```

여기서 비교 대상은 action-level query다.

```text
Action-level query:
  "이 행동을 해도 될까?"
  현재 로봇이 어떤 hidden state를 잘못 알고 있는지 명시적으로 잡지 못함.

State-level query:
  "이 predicate가 참인가?"
  예: ripe(tomato3), at(tomato2, stem_01), paper(waste1)
  사용자의 응답이 특정 state variable / predicate로 들어가 belief update에 직접 반영됨.
```

실험으로 보여줄 것:

```text
상태 단위 query가 action-level query 또는 KnowNo-style query보다
성공률, 질문 수, planning length에서 더 나은가?
```

## 6. 실험 2: What - Query Content / Search Strategy

### 목적

```text
로봇이 무엇을 질문해야 하는지 스스로 고르는 메커니즘을 보여준다.
```

우리 방식:

```text
action frontier 위의 belief entropy를 보고,
현재 action 선택에 영향을 주는 predicate를 query 대상으로 고른다.
```

비교 후보:

```text
Active Search:
  query/search/sensing action을 planning 안에 포함.

Search ablation:
  1개씩 묻기
  여러 개 후보 묻기
  heuristic 기반 선택
  random predicate 선택
```

Metrics:

```text
success rate
query count
query ratio
planning length
search time
elapsed time
failure / dead-end rate
```

논문에서 말할 것:

```text
query content는 단순히 아무 predicate나 묻는 것이 아니라,
현재 planning decision에 영향을 주는 state uncertainty를 골라야 한다.
```

Active Search와의 차이:

```text
Active Search:
  information acquisition 자체를 action 후보로 넣기 때문에 search space가 커짐.

Ours:
  physical planning은 유지하고,
  uncertainty가 높은 frontier에서 query content를 선택함.
```

주의:

```text
여기서 Active Search는 "How"가 아니라 "What / search strategy" baseline에 가깝다.
```

## 7. 실험 3: How - State-Level Query Format

### 목적

```text
상태 단위 query가 action-level query보다 planning에 더 효과적인지 보여준다.
```

PPT의 문제 제기:

```text
행동 수준의 질문은 로봇이 현재 어떤 상태를 가지고 있는지를 충분히 반영하지 못해서,
잘못된 행동을 물어보게 만든다.
```

비교 대상:

```text
Ours:
  state-level / predicate-level query
  예: ripe(tomato1)=True?, paper(waste2)=True?

KnowNo / Conformal Prediction:
  다음 행동 후보가 여러 개일 때 사용자에게 질문
  action-level 또는 option-level uncertainty query
```

핵심 차이:

```text
KnowNo:
  현재 상태에 대한 불확실성을 명시적으로 다루지 않음.
  action choice uncertainty를 통해 질문.

Ours:
  state / predicate uncertainty를 명시적으로 다룸.
  사용자의 응답이 특정 state variable에 대응되어 belief update에 들어감.
```

Metrics:

```text
success rate
query count
query ratio
planning length
operation time
query probability per step
```

User study가 포함되면:

```text
perceived workload
response time
NASA-RTLX
fatigue
situation awareness
```

논문에서 말할 것:

```text
state-level query는 단순히 "이 행동을 할까요?"보다
오류의 원인이 되는 hidden predicate를 직접 수정하므로
planning failure를 구조적으로 줄일 수 있다.
```

이 실험은 `When / What / How`의 main contribution은 아니다.

비교:

```text
oracle
noisy-oracle

```

논문에서의 위치:

```text
oracle:
  main experiments의 기본 feedback source

noisy-oracle:
  answer가 완벽하지 않을 때 성능이 얼마나 떨어지는지 보는 robustness analysis

human-proxy:
  논문 main result에는 넣지 않음
  appendix 또는 internal analysis
```

Human-Proxy 해석:

```text
Human-Proxy는 contribution이 아니다.
Oracle result가 human feedback setting으로 연결될 수 있는지 확인하는 evaluation device다.
```

Metrics:

```text

dead-end rate
query count
planning length
answer error rate
belief confidence after feedback
```

주의:

```text
baseline comparison에는 answer noise를 섞지 않는다.
baseline comparison은 oracle answer로 고정한다.
```

## 16. 2026-07-09 현재 구현/정리 현황

### 16.1 Observation confidence 모델

Tomato / wastesorting 도메인에서 observation distribution을 고정 확률표가 아니라
센서 confidence처럼 해석할 수 있게 정리했다.

```text
핵심 의도:
  실제 perception system처럼 observation마다 confidence가 달라질 수 있음.
  true positive는 비교적 높은 confidence.
  false positive / ambiguous detection은 낮은 confidence.
  belief update에서는 각 관측 fact의 likelihood로 사용.
```

구현 상태:

```text
scripts/models/observation.py:
  Observation / ObservationOutcome에 fact_confidences 추가.

scripts/models/tomato/obs.py:
  detector-style confidence 모델로 재작성.

scripts/models/wastesorting/obs.py:
  tomato template을 따라 detector-style confidence 모델로 재작성.
  wastesorting에는 scan action이 없으므로 detect / manipulation 중심으로 정리.
```

해석:

```text
현재 likelihood 계산은 각 observed fact를 독립 Bernoulli observation처럼 근사한다.
이것은 실제 로봇에서도 내부 belief update 알고리즘의 근사로 볼 수 있다.
지금 당장 정규분포 기반 likelihood로 바꿀 필요는 없다.
```

### 16.2 Transition duplicate 처리

```text
scripts/models/transition.py:
  get_next_state_distribution 결과에서 동일한 world/state가 중복될 경우 제거/merge하도록 정리.
```

의미:

```text
Transition outcome은 실제 env에서 가능한 next state distribution이어야 한다.
동일 world가 중복으로 남으면 belief frontier와 confidence 해석이 흔들릴 수 있다.
```

## 17. Human-Proxy 응답 모델: Difficulty to Softmax Probability

### 17.1 목적

`human-proxy`는 oracle처럼 항상 맞는 응답자가 아니라, 질문 상황의 난이도에 따라 답변이 흔들리는 사람을 근사한다.

핵심은 다음이다.

```text
질문 상황이 쉬움:
  정답 방향의 확신이 큼
  oracle answer와 거의 같게 답함

질문 상황이 어려움:
  정답 방향의 확신이 약함
  답변이 0.5에 가까워짐
```

이 모델은 실제 인간의 내부 확신도를 직접 관측할 수 없기 때문에, 각 상황별 난이도를 도메인 지식과 기존 유저스터디 경향을 참고해 proxy로 설정한다.

### 17.2 이론적 배경

인간이 로봇의 질문 상태 `s`에 대해 `Yes` 또는 `No` 중 하나를 고른다고 하자.
이때 인간이 각 답변에 대해 갖는 주관적 확신도 또는 유틸리티를 다음과 같이 둔다.

```text
Q(s, Yes)
Q(s, No)
```

그러면 인간이 `Yes`라고 답할 확률은 softmax로 표현할 수 있다.

```text
P(Yes | s)
= exp(Q(s, Yes) / tau)
  /
  (exp(Q(s, Yes) / tau) + exp(Q(s, No) / tau))
```

여기서 `tau`는 인간 응답의 일관성 또는 내부 노이즈를 나타내는 rationality parameter다.

```text
tau가 작음:
  같은 Q 차이에서도 더 일관되게 큰 Q 쪽을 고름

tau가 큼:
  같은 Q 차이에서도 더 무작위에 가까워짐
```

이진 선택에서는 실제로 중요한 값이 `Q(s, Yes)`와 `Q(s, No)`의 차이다.
따라서 위 식은 다음처럼 sigmoid 형태로 볼 수 있다.

```text
P(True) = sigmoid(beta * (u(True) - u(False)))
```

실제 구현에서는 `beta`와 utility 차이를 따로 튜닝하지 않고, 둘을 합친 하나의 스칼라를 `margin`으로 둔다.

### 17.3 Difficulty to Margin

질문 난이도 `difficulty`는 `0~10` 범위로 둔다.

```text
difficulty = 0:
  가장 쉬운 질문
  oracle에 가까운 확신

difficulty = 10:
  가장 어려운 질문
  coin-flip에 가까운 응답
```

난이도가 높을수록 정답 방향 margin이 작아지도록 선형으로 매핑한다.

```python
def margin(difficulty, m_max=4.0):
    # difficulty: 0~10, 높을수록 어려움
    return m_max * (1 - difficulty / 10)
```

의미:

```text
d=0  -> margin = m_max
d=10 -> margin = 0
d=8  -> margin = m_max * 0.2
```

현재 tomato 구현에서는 기본값을 다음처럼 둔다.

```python
HUMAN_PROXY_M_MAX = 4.0
HUMAN_PROXY_CRITERION = 0.0
```

`m_max=4.0`이면 난이도 0에서 정답 확률은 다음과 같다.

```text
P(correct) = sigmoid(4.0) = 0.9820
```

만약 난이도 0에서 `P(correct)=0.99`를 원하면:

```python
target_p = 0.99
m_max = math.log(target_p / (1 - target_p))  # ~= 4.595
```

### 17.4 Sampling Logic

구현은 oracle answer의 방향을 먼저 잡고, 그 방향으로 margin을 부여한다.

```python
def sample_human_proxy_answer(
    oracle_answer: bool,
    difficulty: int,
    m_max=4.0,
    criterion=0.0,
):
    s = 1.0 if oracle_answer else -1.0
    m = m_max * (1 - difficulty / 10)
    logit = s * m + criterion
    p_true = 1 / (1 + math.exp(-logit))
    return random.random() < p_true
```

해석:

```text
oracle_answer=True:
  logit이 양수
  P(answer=True)가 0.5보다 큼

oracle_answer=False:
  logit이 음수
  P(answer=True)가 0.5보다 작음

difficulty가 커짐:
  margin이 작아짐
  P(answer=True)가 0.5에 가까워짐
```

### 17.5 예시

질문:

```text
ripe(tomato1)=True?
```

조건:

```text
oracle_answer = True
difficulty = 8
m_max = 4.0
criterion = 0.0
```

계산:

```text
margin = 4.0 * (1 - 8 / 10) = 0.8
logit = 0.8
P(answer=True) = sigmoid(0.8) ~= 0.69
P(answer=False) ~= 0.31
```

즉 난이도 8은 거의 coin-flip에 가깝지만, 정답 방향으로 약간 치우친 질문으로 해석한다.

### 17.6 파라미터 의미

| 파라미터 | 의미 | 조정 시 효과 |
|---|---|---|
| `m_max` | 난이도 0일 때 정답 방향 확신의 최대 margin | 크게 잡을수록 쉬운 질문은 oracle과 거의 같아짐 |
| `difficulty` | 0~10 질문 난이도 | 높을수록 margin이 작아지고 답변이 0.5에 가까워짐 |
| `criterion` | Yes로 답하려는 전역 편향 | 양수면 애매할 때 Yes 쪽, 음수면 No 쪽으로 치우침 |
| `s` | oracle 정답 방향 | `True`면 +1, `False`면 -1 |

## 18. Softmax / Boltzmann Response의 이론적 배경

미팅 PPT에서 human-proxy 응답 모델을 설명할 때 사용할 수 있는 이론적 배경이다.
핵심은 `exp(beta * u(i))` 형태가 임의로 만든 함수가 아니라, 여러 관점에서 자연스럽게 나오는 확률 선택 모델이라는 점이다.

### 18.1 기본 형태

선택지 `i`의 효용 또는 주관적 확신도를 `u(i)`라고 하면, softmax response model은 다음과 같다.

```text
P(i) = exp(beta * u(i)) / sum_j exp(beta * u(j))
```

이진 질문에서는 선택지가 `Yes`, `No` 두 개뿐이므로:

```text
P(Yes | s)
= exp(beta * u(Yes))
  /
  (exp(beta * u(Yes)) + exp(beta * u(No)))
```

또는 temperature `tau`를 쓰면:

```text
P(Yes | s)
= exp(Q(s, Yes) / tau)
  /
  (exp(Q(s, Yes) / tau) + exp(Q(s, No) / tau))
```

여기서:

```text
Q(s, Yes), Q(s, No):
  질문 상태 s에서 인간이 Yes/No 각각에 대해 갖는 주관적 확신도

tau:
  응답 일관성 또는 내부 노이즈

beta:
  inverse temperature
  beta = 1 / tau 로 볼 수 있음
```

이진 softmax는 결국 두 값의 차이만 중요하다.

```text
P(Yes | s) = sigmoid((Q(s, Yes) - Q(s, No)) / tau)
```

즉 실제 응답 확률은 다음 값으로 결정된다.

```text
(Q(s, Yes) - Q(s, No)) / tau
```

### 18.2 관점 1: Statistical Mechanics / Boltzmann Distribution

Boltzmann이라는 이름은 통계역학에서 온다.
통계역학에서 어떤 계가 에너지 `E(i)`를 가진 상태 `i`에 있을 확률은 다음과 같이 주어진다.

```text
P(i) = exp(-E(i) / kT) / sum_j exp(-E(j) / kT)
```

여기서:

```text
E(i):
  상태 i의 에너지

T:
  온도

k:
  Boltzmann constant
```

의미:

```text
에너지가 낮은 상태일수록 확률이 높다.
하지만 온도 T가 높으면 상태 간 확률 차이가 흐려진다.
```

의사결정 모델에서는 이를 다음처럼 해석한다.

```text
낮은 에너지 = 높은 효용
u(i) = -E(i)
beta = 1 / kT
```

따라서:

```text
beta가 큼:
  온도가 낮음
  요동이 작음
  거의 최적 선택만 함

beta가 작음:
  온도가 높음
  요동이 큼
  선택이 더 무작위에 가까움
```

human-proxy에 대응시키면:

```text
beta가 큼 / tau가 작음:
  사람이 자신의 확신도 차이를 일관되게 따른다.

beta가 작음 / tau가 큼:
  같은 확신도 차이가 있어도 답변이 더 흔들린다.
```

### 18.3 관점 2: Maximum Entropy Principle

Maximum Entropy 관점에서는 다음 질문에서 시작한다.

```text
우리가 아는 것은 선택지의 기대 효용 제약뿐이다.
그 외에는 추가 가정을 최대한 하지 않으려면
어떤 확률분포를 써야 하는가?
```

즉 다음 조건을 만족하면서 엔트로피가 가장 큰 분포를 찾는다.

```text
1. 확률의 합은 1
2. 기대 효용은 주어진 값
3. 그 외에는 가능한 한 편향을 넣지 않음
```

이 최적화 문제를 라그랑주 승수법으로 풀면 exponential family 형태가 나온다.

```text
P(i) ∝ exp(beta * u(i))
```

정규화하면 softmax가 된다.

```text
P(i) = exp(beta * u(i)) / sum_j exp(beta * u(j))
```

의미:

```text
효용이 높은 선택지를 더 자주 고른다는 제약만 유지하면서,
그 외의 불필요한 가정은 최소화하면 softmax 형태가 나온다.
```

human-proxy에 대응시키면:

```text
질문 상태 s에서 Yes/No에 대한 주관적 확신도만 주어졌을 때,
그 확신도 차이를 반영하되 추가 구조를 최소화한 응답 분포가 softmax다.
```

### 18.4 관점 3: Random Utility Model

Random Utility Model 관점에서는 사람이 실제로는 가장 큰 효용을 가진 선택지를 고른다고 본다.
다만 관찰자가 그 효용을 완벽히 알 수 없어서, 관측되지 않는 요인을 noise로 둔다.

```text
u_tilde(i) = u(i) + epsilon(i)
```

여기서:

```text
u(i):
  관찰자가 모델링한 효용 또는 확신도

epsilon(i):
  관찰하지 못한 요인
  예: 순간적 피로, 애매한 시각 정보, 조명, 판단 흔들림
```

사람은 내부적으로 다음을 고른다고 볼 수 있다.

```text
argmax_i u_tilde(i)
```

이때 `epsilon(i)`가 i.i.d. Gumbel distribution을 따른다고 가정하면,
관찰자 입장에서의 선택 확률이 softmax 형태가 된다.

```text
P(i) = exp(beta * u(i)) / sum_j exp(beta * u(j))
```

의미:

```text
사람의 선택은 내부적으로는 효용이 큰 쪽을 따른다.
하지만 우리가 모든 요인을 완벽히 모델링하지 못하기 때문에,
겉으로는 확률적 선택처럼 보인다.
```

human-proxy에 대응시키면:

```text
Q(s, Yes), Q(s, No)는 우리가 모델링한 주관적 확신도다.
실제 응답에는 우리가 모델링하지 못한 요인이 남아 있고,
그 결과 응답 확률을 softmax로 표현한다.
```

### 18.5 파라미터 의미 정리

| 파라미터 | 의미 | 극단값 해석 |
|---|---|---|
| `u(i)` 또는 `Q(s, i)` | 선택지 `i`에 대한 주관적 효용/확신도 | 값이 클수록 그 답변을 더 그럴듯하게 느낌 |
| `beta` | inverse temperature, 선택 일관성 | `beta -> infinity`: 거의 항상 높은 효용 선택 / `beta -> 0`: 거의 uniform random |
| `tau` | temperature, 응답 노이즈 | `tau -> 0`: 결정론적 응답 / `tau -> infinity`: 무작위 응답 |
| `Z = sum_j exp(beta * u(j))` | partition function, 정규화 상수 | 모든 선택지 점수를 확률분포로 변환 |

`beta`와 `tau`는 같은 역할을 반대 방향으로 표현한 것이다.

```text
beta = 1 / tau
```

따라서:

```text
beta가 커짐 = tau가 작아짐 = 더 일관된 응답
beta가 작아짐 = tau가 커짐 = 더 랜덤한 응답
```

### 18.6 본 연구의 Human-Proxy 해석

본 연구에서는 softmax response를 다음처럼 해석한다.

```text
로봇이 상태 predicate에 대해 질문한다.
인간 proxy는 Yes/No 각각에 대한 주관적 확신도를 갖는다.
질문이 쉬우면 정답 방향 확신도가 크게 벌어진다.
질문이 어려우면 Yes/No 확신도 차이가 작아진다.
softmax는 이 확신도 차이를 실제 응답 확률로 변환한다.
```

실제 구현에서는 `Q(s, Yes) - Q(s, No)`를 직접 만들기보다,
질문 난이도에서 정답 방향 margin을 만든다.

```text
margin = m_max * (1 - difficulty / 10)
```

그리고 oracle answer 방향으로 margin의 부호를 정한다.

```text
oracle_answer=True:
  logit = +margin + criterion

oracle_answer=False:
  logit = -margin + criterion
```

최종 응답:

```text
P(answer=True) = sigmoid(logit)
```

이 방식은 위 softmax 모델의 이진 형태와 동일하다.
