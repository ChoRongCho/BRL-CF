# 2026-07-08 Detector Confidence 기반 Observation TODO

## 1. 문제 정의

현재 observation model은 도메인별로 고정 확률을 사용한다.

예를 들어 watering `find_plant`는 다음처럼 항상 같은 확률을 쓴다.

```text
실제로 방 안에 plant가 있음:
  at(P,R) 관측: 0.90
  miss / detect 안 됨: 0.10

실제로 방 안에 plant가 없음:
  false positive at(P,R): 0.05
  empty observation: 0.95
```

하지만 실제 로봇 시스템에서는 observation이 단순히 True/False로만 나오지 않는다.
YOLO 같은 detector는 detection 결과와 함께 confidence를 낸다.

토마토 수확 도메인 예시:

```text
detect_tomato 결과:
  tomato1 ripeness=ripe confidence=0.93
```

이 경우 `ripe(tomato1)`일 확률을 0.93 정도로 해석할 수 있다.
bounding box confidence까지 엄밀히 분리하지는 않고, 우선 ripeness confidence를
observation likelihood로 사용한다.

## 2. 목표

고정된 observation 확률 대신, detector가 반환한 confidence를 belief update와
질문 판단에 사용한다.

핵심 목표:

- confidence가 높으면 observation을 강하게 믿는다.
- confidence가 낮으면 belief가 애매하게 남고, human query가 발생할 수 있다.
- 없는 object에 대한 false positive도 가능하게 둔다.
- 단, false positive의 confidence가 낮으면 시스템이 불확실함을 인지해야 한다.
- 만약 실제 detector가 없는 object에 대해 confidence 0.93 같은 높은 값을 주면,
  그건 detector가 강하게 틀린 것이므로 planner도 틀릴 수 있다.

즉, 시스템은 항상 정답을 맞히는 것이 목표가 아니라, detector confidence에 맞게
불확실성을 표현하는 것이 목표다.

## 3. 원하는 해석

### 3.1 실제 object가 관측된 경우

예:

```text
true state:
  ripe(tomato1)

detector output:
  ripe(tomato1), confidence=0.93
```

해석:

```text
P(ripe(tomato1) observed | ripe(tomato1) true) = 0.93
P(noisy / uncertain observation)               = 0.07
```

이 경우 confidence가 충분히 높으므로 굳이 human query를 하지 않아도 된다.

### 3.2 실제 object가 없는데 false positive가 나온 경우

예:

```text
scene_01 true_init:
  tomato1, tomato2만 존재

detector output:
  tomato3 ripeness=ripe confidence=0.64
```

해석:

```text
tomato3가 실제로 있을 가능성을 낮거나 중간 정도로만 둔다.
ripeness도 확신하지 않는다.
belief confidence가 낮으므로 query 대상이 될 수 있다.
```

없는 tomato3가 관측될 수는 있다.
다만 일반적으로 detector가 애매한 false positive를 만들면 confidence가 0.6~0.7
정도로 낮게 나와야 한다.

### 3.3 detector가 높은 confidence로 틀린 경우

예:

```text
detector output:
  tomato3 ripeness=ripe confidence=0.93

하지만 true state에는 tomato3가 없음
```

이 경우는 detector가 강하게 틀린 상황이다.
시스템이 잘못 믿고 행동할 수 있다.
이건 모델링 오류가 아니라 실제 perception failure로 취급한다.

## 4. 모델링 전략

### 4.1 Observation 결과에 confidence를 붙인다

현재 observation은 보통 fact set 형태다.

```text
{ripe(tomato1)}
```

이를 confidence가 있는 observation으로 확장한다.

```text
{
  ripe(tomato1): 0.93
}
```

여러 후보가 있으면 각각 confidence를 가진다.

```text
{
  ripe(tomato1): 0.93,
  unripe(tomato2): 0.71,
  ripe(tomato3): 0.64
}
```

### 4.2 Confidence를 likelihood로 사용한다

belief update에서 hard True/False 대신 confidence를 likelihood로 쓴다.

예:

```text
observation: ripe(tomato1), confidence=0.93

state가 ripe(tomato1)을 포함하면:
  likelihood *= 0.93

state가 ripe(tomato1)을 포함하지 않으면:
  likelihood *= 0.07
```

이렇게 하면 confidence가 낮은 observation은 belief를 약하게만 움직인다.

### 4.3 Query 기준은 belief confidence로 둔다

human query는 raw detector confidence 하나만 보고 결정하지 않는다.
최종 belief confidence가 낮을 때 질문한다.

예:

```text
belief P(ripe(tomato1)) = 0.94 -> query 안 함
belief P(ripe(tomato1)) = 0.67 -> query 함
```

threshold는 실험 설정으로 둔다.

```text
query_threshold = 0.80
```

### 4.4 False positive confidence 분포를 따로 둔다

실제 object에 대한 정상 detection과, 없는 object에 대한 false positive는 confidence
분포가 달라야 한다.

예:

```text
true positive confidence:
  대체로 0.85 ~ 0.98

ambiguous false positive confidence:
  대체로 0.55 ~ 0.75

rare high-confidence false positive:
  낮은 확률로 0.85 ~ 0.95
```

rare high-confidence false positive는 detector가 강하게 틀리는 경우를 표현한다.

## 5. 도메인별 적용 방향

### 5.1 Tomato

YOLO detector가 tomato object와 ripeness를 함께 준다고 가정한다.

관측 예:

```text
ripe(tomato1): 0.93
unripe(tomato2): 0.74
rotten(tomato3): 0.62
```

사용 방식:

- confidence가 높은 ripeness는 query 없이 belief update
- confidence가 낮은 ripeness는 query 후보
- true_init에 없는 tomato가 관측되면 false positive로 처리
- false positive confidence가 낮으면 불확실한 belief로 남김
- false positive confidence가 높으면 실제 perception failure로 허용

### 5.2 Watering

`find_plant`도 같은 구조로 확장할 수 있다.

관측 예:

```text
at(plant1,living_room): 0.91
at(plant2,living_room): 0.63
```

현재처럼 plant별 독립 observation 구조는 유지하되, 각 observation에 고정 확률이
아니라 detector confidence를 붙인다.

## 6. 구현 계획

### 6.1 Observation 객체 확장

fact만 담는 observation과 confidence observation을 구분한다.

예:

```python
@dataclass
class ConfidenceObservation:
    fact: str
    confidence: float
```

또는 dict 형태:

```python
dict[str, float]
```

초기 구현은 dict가 단순하다.

### 6.2 Answer oracle / human query와 연결

human query는 confidence가 낮은 fact에 대해서만 발생하도록 한다.

예:

```text
P(fact | belief) < query_threshold -> 질문
P(fact | belief) >= query_threshold -> 질문 생략
```

### 6.3 Detector confidence sampler 추가

실제 YOLO가 없으므로 simulation에서는 confidence를 샘플링한다.

예:

```text
true positive:
  confidence ~ high confidence distribution

false positive:
  confidence ~ ambiguous confidence distribution

rare false positive:
  confidence ~ high confidence distribution, low probability
```

### 6.4 Log에 confidence 저장

각 observation마다 confidence를 반드시 기록한다.

예:

```text
[Observation]
  ripe(tomato1): confidence=0.93
  ripe(tomato3): confidence=0.64 false_positive=True
```

이 기록이 있어야 query가 왜 발생했는지, belief가 왜 틀어졌는지 추적할 수 있다.

## 7. 검증 계획

확인할 것:

- confidence 0.93 observation은 belief를 강하게 업데이트하는가?
- confidence 0.60 observation은 belief를 약하게 업데이트하는가?
- 낮은 confidence에서는 human query가 발생하는가?
- 높은 confidence에서는 human query가 생략되는가?
- true_init에 없는 tomato3 false positive가 낮은 confidence로 들어올 수 있는가?
- rare high-confidence false positive가 들어오면 planner가 실제로 틀릴 수 있는가?
- observation log에 fact와 confidence가 같이 남는가?

## 8. 권장 구현 순서

1. observation 표현에 `fact -> confidence` 구조를 추가한다.
2. tomato domain에서 ripeness observation만 먼저 confidence 기반으로 바꾼다.
3. belief update likelihood가 confidence를 쓰도록 연결한다.
4. query threshold를 추가해서 낮은 confidence에서만 질문하게 한다.
5. false positive confidence sampler를 추가한다.
6. observation log에 confidence를 출력한다.
7. watering `find_plant`에도 같은 구조를 적용한다.
